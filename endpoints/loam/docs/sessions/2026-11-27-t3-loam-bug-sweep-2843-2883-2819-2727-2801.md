- Date: 2026-11-27

- Pull request: [#3041](https://github.com/lushly-dev/afd/pull/3041), on `t3/loam-bug-sweep-2843-2883-2819-2727-2801`, for [#2843](https://github.com/lushly-dev/afd/issues/2843), [#2883](https://github.com/lushly-dev/afd/issues/2883), [#2819](https://github.com/lushly-dev/afd/issues/2819) and [#2727](https://github.com/lushly-dev/afd/issues/2727)

**#2883 (switcher reopens on a second press):** the switcher's button notes whether the list was
open when a pointer went down on it, and a pointer's click from such a press (`detail` above 0)
closes the list and never reopens it, however long it is held. A key's press and Mod+Alt+P toggle
it as before. This replaces the list's 300 ms `justClosed` window, which missed a slow click and,
in review's first fix, swallowed Enter right after Shift+Tab. A rail test covers a quick and a held
second press, Shift+Tab then Enter, and Escape then Enter. Its first form failed before the fix
(`aria-expanded` stayed `true`).

**#2843 (autonomy test times out under load):** a real race, not only a slow poll. Every
`autonomy-set` emits `settings: ['loam.autonomy']`, and the settings view reads the section again,
which drew the add-rule form anew on its first app: CI's `[ 'Every command', …(4) ]` was hello's
commands after `tally` had been chosen. The form now keeps its app, command and mode across a read
again, as a draft kept by scope and level (`chrome/src/settings/autonomy.ts`), so neither two reads
while its command list is still coming nor a move to another project changes it, and Add rule sends
nothing until the list has come. Tests set the cap from outside with a rule half made and find it
kept (it failed before: `expected 'hello' to be 'tally'`), and hold the command list across two
reads. The file's polls wait up to 10 s. Four copies of the file beside the rail suite passed together.

**#2727 (export journals before a save it saw):** `journal-order.ts`'s `read()` now counts a nested
read toward its top-level call, as `wrote()` does; under a mutation it adds nothing.
`document-export` and the copilot's `readAttachment` no longer read `doc-stamp`, which their answers
do not carry; otherwise the save's stamp's WAR edge would make the new RAW edge a cycle, which is
dropped. A nested call that suspends for a person now drops its root's reads too, so a write made
while the person answers is not held. A nested read under a call a replay answers from its record
(`REPLAY_RECORDED_QUERIES`, now in `replay-recorded.ts`, and `copilot-*`) adds nothing: review found
`project-summary-get`'s summaries otherwise held a write to their stores up to the 2 s deadline,
which P2-D9 caught. Replay-parity cases for `document-export` beside
`probe-content-set` (one failed before: journaled first) and unit cases in `journal-order.test.ts`.

**#2819 (notes-conflict `$fastController` null locally):** not reproduced on Windows at this base
(3 of 3 runs of the three themes). It was seen at `ed1d52eac`, before
[#2868](https://github.com/lushly-dev/afd/pull/2868) (#2444's fix to the same job's shell start)
merged, and #2868 reports 20 of 20 runs of the job on the Mac. The check here ran on Windows only,
so the pull request closes #2819 on that evidence; reopen it if it fails on the Mac again.
