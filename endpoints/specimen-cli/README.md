# Specimen CLI endpoint

**Preview,** like [Specimen](../../foundations/specimen/README.md): the commands can still change. Install it with `npm install @lushly-dev/specimen-cli@preview`, then Chromium's headless shell as [Specimen's install](../../foundations/specimen/README.md#install) describes.

Install `@lushly-dev/specimen-cli` to obtain the `specimen` binary. The commands include `list`, `validate`, `inspect ID`, `render ID`, `capture [IDS...]`, `compare ID1 ID2...`, `review BEFORE AFTER`, `run ID`, `a11y [ID]`, `themes [ID]`, `migrate`, `diff LEFT.json RIGHT.json`, `build OUTDIR`, `pack [TAG]`, `pack-check [TAG]`, `pack-export DIR`, `point`, `point-move ID TO`, `point-check ID`, `note-add`, `note-list`, `note-check [SPECIMEN]`, `note-move ID TARGET`, `note-resolve ID`, `note-reopen ID`, `job-create ID`, `job-run ID`, `decision-record`, `decision-get ID`, `decision-list` and `decision-check`. Option validation, one CommandResult JSON value on stdout, atomic output files, and exit codes (0 success, 1 failure) are unchanged. `runCli` and `CliIO` are exported for embedding and testing. This endpoint composes Specimen and AFD through `@lushly-dev/specimen-afd`. The inspected application does not need those endpoint dependencies.

```sh
specimen list --root ./component-project
specimen validate --root ./component-project --file src/button.stories.ts
specimen render button --root ./component-project --viewport 375x812
specimen job-create notes-draft --scenario ./scenarios/keep-a-draft.scenario.yaml --module ./app.specimens.ts --export-name NotesApp --target app --captures 3,4
specimen job-run notes-draft --label main
specimen render notes-draft --set main --checkpoint conflict-notice
specimen a11y --set main
```

`list` lists discovered specimens, retained stories, jobs, and synthesized pattern gate cases; `--kind story|native|gate|component|job`, `--component TAG`, `--pattern REF`, `--match TEXT`, `--limit N`, and `--after CURSOR` filter and paginate results.

`validate` checks the retained stories, guides, jobs, and pattern files a configuration discovers, statically; `--id ID` or `--file PATH` narrows it to one story or file. A report with errors is still a successful command: `data.valid` is `false` and each issue carries a suggestion.

`coverage [TAG]` runs the selected cases and reports each component's required partitions (`schema-partitions@1`), optional guide obligations (`guides@1`), and optional pattern gate coverage (`patterns@1`). `--file`, `--tag`, `--match`, `--pattern REF` and `--workers` narrow it. With `--obligations jobs@1 --captures SET` (a set id or local label), it reads recorded job captures from that set with no browser and reports `components[].jobs` (`reachedBy`, `unreached`, and `reason` when no job renders a component), applying `unreached:<partition>` waivers.

`pack [TAG]` builds the configured library's component pack (Specimen's `pack` key) from two passes over every case and writes its committed records; `TAG` rebuilds one record from the cases the last full build indexed. `--allow-failed A,B` names cases allowed to fail, and `--workers N` limits how many run at once. `pack-check [TAG]` builds the same way, writes nothing, and exits 1 when a committed record differs or a case failed: the drift check. `pack-export DIR` writes the exported form from the committed records with no browser, with `--revision SHA` recorded in its catalog, and refuses when the manifest or a guide file says something the records do not.

`contract [TAG]` reports what FAST-AF's Fastbot story contract would, on evidence from a run, and exits non-zero when it is not valid. `--file`, `--tag`, `--match` and `--workers` narrow it.

`themes [ID]` renders entries in each theme and compares the screenshots: which follow the theme, which stay the same and declare it with a `light-only`, `dark-only` or `high-contrast-only` tag, and which stay the same with nothing declaring it. `--theme light,dark` picks the themes (default all three), `--threshold 0.02` the share of pixels at or under which two frames count as the same, and `--file`, `--tag`, `--match` and `--workers` select and run entries as `a11y` does. It exits 1 when an entry is `undeclared`; read each report's `status`.

`suggest [TAG]` proposes native specimens and claims for a component's gaps, or placeholder pattern gate setup stubs (including tagless consumer cases with `--pattern REF --gaps pattern:...`), always as unverified. `--gaps A,B` names them, or a coverage run finds them, and `--out FILE` saves the module, never over an existing file.

`migrate` previews the codemod over the configured story files; `--files A,B` narrows it, `--helpers` switches helper and type imports instead of naming components, and `--apply` writes the proposals. `inspect ID` reports an entry's resolved args, context and component schema without rendering it. `matrix ID` captures one entry once per combination of comma-separated `--theme`, `--viewport`, `--container`, `--locale`, `--reduced-motion` and `--motion` values, with `--workers N`, and compares each cell with the first; an unavailable cell stays in the report. `profile [ID]` measures entries at `--checkpoint` (default `mount`) over `--runs N` fresh runs (default 3), and compares with a recorded baseline; with no ID or selection it profiles everything that has one. `baseline ID` records the results in the file `profile.baselines` names, with `--note TEXT`. A failed budget or a broken run exits 1. `a11y [ID]` runs an accessibility check at `--checkpoint` (default `after-run`), on one entry or those `--file`, `--tag` and `--match` select, with `--workers N`; a failed check exits 1. `run` without an ID runs a suite: `--file PATH`, `--tag A,B`, `--kind story,gate`, `--pattern REF` and `--match TEXT` select stories and synthesized gate cases, `--workers N` limits how many run at once, `--retry` retries up to `--flake-cap N` failures once (default 2), and `--capture all|failed|none` chooses which cases keep a capture (default `failed`). A run whose cases failed exits 1. `run ID` runs a retained story or synthesized pattern gate case, and takes the same context options as `render` except `--checkpoint`, plus `--capture all|failed|none` (default `none` for gates, `all` for stories). `render` also accepts `--container`, `--theme`, `--locale`, `--reduced-motion`, `--motion`, `--checkpoint` and `--screenshot`. Context values pass through the shared schema, so a misspelled theme or an invalid locale tag fails before a browser starts.

`point` resolves either a `specimen:` pointer URI copied from the review page (`specimen point "specimen:..."`) or a specimen id with `--role`/`--name` or `--selector` and optional context flags, writes `.specimen/points/pt-<id>.json`, and returns a bounded `Point` record. `point-move ID TO [--index N]` checks staleness first (`POINT_STALE`) and moves the point to `parent`, `child`, `next`, `previous` or `component`. `point-check ID` re-renders in the point's stored context and reports `current` or `stale` with changed files or identity layers. `note-add (--point ID | --pointer URI) --text TEXT [--assignee NAME]` pins a committed note in `specimens/notes/note-<id>.json` (refusing `NOTE_EMPTY` and `POINT_STALE`); `note-list` filters and pages committed notes without launching a browser; `note-check [SPECIMEN]` re-resolves open notes and reports `orphaned`, `weakened`, `unchecked`, and `restored`; `note-move` re-pins a note with `--reason`; `note-resolve` closes one (`ID`) or many (`--ids A,B`) with `--outcome` and `--reason` (`--revision`, `--capture`); `note-reopen ID --reason TEXT` reopens a resolved note keeping its prior resolution in `history`. Each CLI call starts a fresh bench; agents checking points or notes repeatedly should call `specimen-point`, `specimen-point-move`, `specimen-point-check`, and `specimen-note-*` through `endpoints/specimen-server` to keep a warm bench.

`review (BEFORE AFTER | --before SET --after SET) [--ids A,B]` runs a read-only review over two saved capture sets or local labels, excluding kept unchosen variants first (`settled.kept`), grouping changes by structured cause (largest group first, specimen id ascending), surfacing incomplete checks and insufficient evidence, matching committed answer fingerprints (settling `accept` in `settled.answered` and routing `reject` to `blocking`), and linking to `review.html?before=&after=`.

`decision-record` records a choice from a comparison/capture set (`--set`, `--slug`, `--question`, `--chosen`, `--reason`, optional `--files`/`--specimens`/`--tokens`), supersedes one or more current choices (`--supersedes ID[,ID...]`), or answers review items (`--items`, `--chosen accept|reject`, `--reason`), writing committed JSON under `specimens/decisions/` and evidence screenshots + manifests under `specimens/evidence/<set>/` without running `git commit` (CLI calls record `decidedBy: { kind: 'script' }`; brace globs such as `src/**/*.{ts,css}` stay intact inside `--files`). `decision-get ID` reads a decision with its committed evidence captures, `decision-list` lists current choices sorted by id ascending with stale subject globs and undecided comparison sets, and `decision-check` returns current choices covering the given `--files`, `--specimens`, or `--tokens` before editing.

Chromium is required when rendering, not for importing or listing. Browser installation remains explicit; this package has no install hooks. See [the unreleased transition](../../docs/features/complete/platform-monorepo/specimen-transition.md).
