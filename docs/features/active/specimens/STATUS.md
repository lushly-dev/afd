## Current resource decision

The latest two reuse pairs keep in-process execution as the default. Isolated reuse uses approximately **19–27% more CPU for FAST-AF** and **31–33% more for Lushly**, with higher active peaks than the corresponding in-process jobs. Closing the worker leaves about **43 MiB / 38 MiB** in the coordinator, **88–89% below** the in-process post-close footprint. Reuse saves **19–23% CPU** against the current per-round restart controls. On a quiet host on 2026-10-31 ([T02](cpu-attribution-validation.md)), isolated reuse cost **21.6% more CPU for Lushly** (26.78 versus 22.02 core-seconds, all jobs inside the probe band), with isolated coordinators about 96% idle in the warmed profiles. FAST-AF's same-session figures are held for host noise.

These outcomes support an opt-in worker reused across related captures and explicitly closed afterward. They do not establish a safe number of simultaneous agent sessions. The experimental macOS observer is C. On branch `lush/specimens-t04-optimize`, rendering moves into a Rust host that targets the costs round 0 attributed: Node module loading, Playwright, Vite's development graph and response readback, and the runtime memory an in-process close retained. Its sessions measure whole jobs, so the host's process start and protocol boundary are inside them; packaging prebuilt hosts is not done. The [optimization record](t04-optimization.md) has the measurements; its paired verdict session passes every T04 criterion for both consumers. The confirmed optimization on main is still Vite fallback-map caching.
