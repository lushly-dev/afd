# T05 retained-CSF compatibility slice

**State, 2026-11-01:** in progress. Step 1, discovery and static validation, is implemented on branch `lush/specimens-t05-compat`. The remaining steps are listed [below](#remaining-steps).

T05 lets Specimen run the consumers' existing Storybook stories (CSF files) without rewriting them. Its acceptance comes from the [implementation plan](implementation.md#ordered-implementation-queue) and the proposal's [CSF compatibility contract](../../proposed/specimens/specimens.proposal.md#csf-compatibility-contract):

- the four plugin points are specified and exercised;
- FAST-AF's theme and schema integration;
- identity and field-specific annotation precedence;
- `validate` / `inspect` and a preview-first codemod that keeps metadata;
- both runners agree on representative positive cases and on deliberately failing ones;
- unsupported active semantics fail validation.

## The incumbent in this repository

The two runners are Storybook's own and Specimen's. Storybook 10.6.2 is a development dependency of `@lushly-dev/specimen`, which is Lushly's incumbent version, with its web-components framework, the a11y addon and the Vitest addon. That makes the incumbent runnable in CI as the reference oracle for the fixtures under `foundations/specimen/compat/`. It is never a runtime dependency: the native core still installs without it, and the packed-artifact consumers check that.

`compat/` is a Storybook project of plain custom elements:

- `.storybook/main.ts` and `.storybook/preview.ts` are the incumbent's configuration. The preview applies a theme global through a decorator, sets `a11y.test: 'error'` and adds a project tag, as both consumers' previews do.
- `specimen.config.json` points Specimen at the same files.
- `invalid/<case>/` holds one small project per deliberately failing discovery case, each with its own Storybook configuration.

## Step 1: discovery, identity and static validation

### Configuration

A configuration may now name retained stories beside, or instead of, native specimens:

```json
{
	"stories": ["stories/**/*.stories.ts"],
	"preview": ".storybook/preview.ts"
}
```

Each `stories` entry is a glob, a directory, a file or `{ directory, files, titlePrefix }`, normalized as Storybook's `normalizeStoriesEntry` does, relative to the configuration file. Two differences:

- A directory's default pattern is `**/*.stories.{js,jsx,mjs,ts,tsx}`, because MDX docs pages are not stories.
- Extended globs such as `@(a|b)` fail validation; braces express the same patterns.

`preview` is the project annotations module.

### The indexer

`specimen-host` reads story files statically, with oxc, in a new `index` operation that needs no browser (`host/src/csf`). It follows Storybook 10.6.2's `CsfFile` and story index generator rule for rule, with each function ported from the installed source:

- `storyNameFromExport` start case, `sanitize`, `toId`, `combineTags` and auto-title, held to vectors generated by Storybook's own functions.
- Meta forms: an inline object, a variable, or the object wrapped in `as` / `satisfies`. Meta fields: `title` as a string literal, `id`, `component`, `tags`, `includeStories` and `excludeStories`.
- Story names: a story's `name` counts only as a string literal on its object; `X.storyName = '...'` assignments count; `storyName` inside the object does not. Spreads are not followed, so a story that spreads another inherits neither its name nor its tags in the index.
- `export { Local as Name }` keeps the export name exactly as written. `parameters.__id` overrides an id.
- `__namedExportsOrder` sorts the stories; an order that omits one is an error.
- Tags are Storybook's defaults `dev`, `test` and `manifest`, then the preview's, the meta's and the story's. `play-fn` is added where a `play` is written on the meta or story.

Separately, a static evaluation that follows local constants, spreads and member references reports what each story will do at runtime:

- whether it has a play: `present`, `absent` or `unknown`;
- which annotation fields each level sets;
- which values cannot be read, with the reason (a factory call, an imported binding, an unreadable spread).

Nothing guesses: an unreadable value is `unresolved`.

### Validation

`bench.validate(target?)`, the AFD command `specimen-validate` and `specimen validate [--id ID | --file PATH]` return a static report. Each issue has a severity, a code, a message and a recovery suggestion:

- **Errors** fail validation:
  - discovery failures: unreadable or unparsable files, a dynamic title, duplicate ids, an incomplete export order;
  - CSF features the indexer does not support: re-exported stories, `export *`, CSF factory stories and `Story.test(...)`;
  - unsupported annotations at the project, meta or story level: `loaders`, `beforeAll`, `beforeEach`, `afterEach`, `experimental_afterEach`, `mount`, `runStep`, `argsEnhancers`, `argTypesEnhancers`, `renderToCanvas`, `applyDecorators` and `decorateStory`.
- **Warnings**, such as a file with no stories.
- **Deferred**: values only running the module can settle.

None of the consumers' stories uses an unsupported annotation. Their annotations are `initialGlobals`, `globalTypes`, `parameters` and `decorators` in the project; `title`, `component`, `tags`, `parameters`, `render`, `args`, `argTypes` and `play` in metas; `args`, `play`, `name`, `render`, `globals`, `tags`, `parameters` and `decorators` in stories.

Rules for a bench whose discovery failed:

- `list()`, `render()` and `build()` throw a `DiscoveryError`.
- `validate()` reports each problem instead of throwing.

A retained story is listed with its Storybook identity under `story`. Rendering one fails with `STORY_RENDER_UNAVAILABLE` until step 2. Its module is not bundled yet.

## Storybook behaviour the next steps reproduce

These come from the installed 10.6.2 and 10.3.1 sources and decide the runtime design. A reference with file locations is kept with the local evidence (`test-results/specimens-t05-compat/storybook-semantics.md`, ignored).

- **Three tag computations.** The index adds `manifest` and `play-fn`; the Vitest addon's filter adds `play-fn` but not `manifest`; the runtime adds neither. The addon checks `skip` against the runtime tags.
- **Duplicate ids within one file.** The index keeps the first export; the runtime keeps the last.
- **Accessibility.** Axe runs in an `afterEach` over `document.body`, not the story's canvas, with only the `region` rule disabled. `parameters.a11y.test` defaults to `todo`: violations are warnings unless the policy is `error`, as both consumers set it.
- **Default render.** With a `component` and no `render`, args are set as element properties, never attributes.
- **Teardown.** A story's canvas is cleaned up when the next story starts, not after its own test.
- **Viewport.** The addon's `responsive` viewport resolves to its 1200×900 default, as [T03](driver-context-validation.md) measured.
