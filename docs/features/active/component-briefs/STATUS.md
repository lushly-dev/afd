# Component Briefs: status

Read this before the [proposal](component-briefs.proposal.md). It records exactly what is done and
what is not, so an agent never has to scan the code to learn what is current. It follows the shape
of the [Umbel status](../../../../endpoints/umbel/docs/STATUS.md).

## How to keep this file

- "Done" means merged to `main` with evidence linked. Anything else is "in progress" or "open",
  with what remains spelled out.
- Record how you verified it, the command or check, and the absolute date.
- Write down follow-ups that are not yet issues, with the date and who raised them. Link the issue
  when one exists.
- Never delete history. Mark an entry superseded and point to what replaced it.
- The work spans two areas, each with its own ledger: Specimen's half is
  [T12](../specimens/implementation.md#ordered-implementation-queue) in the
  [Specimens status](../specimens/STATUS.md), and Umbel's half is the
  [`components` plugin specification](../../../../endpoints/umbel/docs/plugins/components/spec.md)
  in the [Umbel status](../../../../endpoints/umbel/docs/STATUS.md). This file holds the plan's
  steps and points to those for the detail; when the two disagree, the area's ledger wins.

## After the owner's decisions

On 2026-11-13 the owner took the recommendations made after C5:

- **Criteria 2 and 10: make the default brief smaller, then rerun before judging.** The reason:
  rebuilt from the history, phase 0's stand-in answered the form page's seven tags in 14 279 bytes
  and the real plugin in 36 619, 2.6 times as much, mostly with what no page was seen to use. Done as
  the plugin specification's A24: a default brief leaves out CSS properties and the rules the
  attributes name (`violet-elements`' 29 `taxonomy.*` rules on that page), writes `property` only
  when it differs from `name`, and says in `omitted` where both are. The rerun, both arms on the same
  base ([record](first-consumer.md#after-c5-a-smaller-default-brief-rerun)):
  - **Criterion 2:** briefs a median 96 % of their declarations, from 113 %; never half. The room
    freed went to the examples the old brief had shed to fit; they are now 27 % of a brief's bytes.
  - **Criterion 10:** as good as today's route (63 against 64) and 15.8 % cheaper (p = 0.19), not 20 %.
    Arm c cost the same as in C5, and arm a moved 4 %. **The brief's size was not the cause:** 6 KB is
    about 5 % of a session's tokens, inside the spread. The hypothesis that it cost the prototype's
    margin was wrong. What is left for the owner is which bar the criteria set: a brief this size
    still saves on the form page (30 %) and not on the dialog page (3 % dearer), and fifteen runs an
    arm do not separate 16 % from 20 % (phase 0's 22.5 % had p = 0.17).
- **How agents find the tool: a hook.** [#1117](https://github.com/lushly-dev/afd/pull/1117): a
  Claude Code project hook refuses the first Write or Edit in a session whose new text uses a
  `violet-*` tag once, naming `components-brief` and the tags, unless the session has briefed. Context
  a hook adds arrives after the write, so it refuses rather than adds. Proved in three real sessions;
  the plugin README describes it.
- **The bench page's budget: no change.** The 50 000-byte ceiling B3 met had already moved to 52 000
