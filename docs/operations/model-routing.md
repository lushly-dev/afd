# Development model routing

Snapshot: 2026-09-29. This guide selects models for agents developing AFD. It does not select models for applications built with AFD. The session's harness owns its work, including delegated implementation and independent review; do not move a task between Codex and Claude Code to obtain a model. Honor a user's explicit model choice and the models actually available in the harness. Pin a delegated model and effort when supported.

Choose the least expensive route likely to complete a bounded deliverable at the required quality. Define the output and its checker before raising effort. API token prices help plan experiments, but total cost depends on reasoning tokens, retries, tool calls, latency, and acceptance. Compare local accepted-task results before declaring one route cheaper or better for AFD work.

| Harness | Starting route | When to change route |
| --- | --- | --- |
| Codex | `gpt-6.1-sol` medium for integrative implementation and ordinary coordination | Use high for contained difficult work with a clear checker. `gpt-6-luna` xhigh remains useful for narrow, specified changes. Pilot Sol xhigh on difficult contained coding only after naming the unresolved invariant, objective checker, stop condition, and the remaining gap after Sol high. `gpt-6-astra` low is a contextual starting point for open-ended or consequential judgment when cheaper routes leave a named question unresolved; raise Astra effort only if that question needs deeper reasoning. Max is never an automatic escalation step. |
| Claude Code | Sonnet 5.5 medium for specified everyday coding and routine coordination | Sonnet high is a candidate for contained difficult coding with a checker. Use Opus 5.5 medium for open-ended architectural or UX judgment and deeper unresolved work; high for consequential assurance. Validate these choices on AFD tasks before treating them as universal reviewer assignments. |

For any delegation, give the agent one bounded deliverable, the files or contract it owns, and a way to verify completion. Escalate on evidence of an unresolved problem, not file count, a label, or a failed command alone. Use a fresh independent reviewer when the task's review workflow requires one. Reviewers report findings and do not edit or run validation; the implementation agent owns corrections and checks.

The [OpenAI GPT-6.1 Sol launch](https://openai.com/index/introducing-gpt-6-1-sol/) reports improvements on coding and professional tasks and API prices of $2 input, $0.10 cached input, and $10 output per million tokens. [Anthropic's Sonnet 5.5 launch](https://www.anthropic.com/claude-sonnet-5-5) describes well-scoped coding as a strength, gives API prices of $2 input and $10 output per million tokens, and says Claude Code defaults to medium effort. [Artificial Analysis's GPT-6.1 Sol snapshot](https://artificialanalysis.ai/articles/gpt-6-1-sol-replaces-gpt-6-sol-after-just-7-days-with-near-astra-intelligence) found stronger coding-agent results at xhigh than max in its evaluation; [its Sonnet 5.5 snapshot](https://artificialanalysis.ai/articles/claude-sonnet-5-5) found that max effort used unusually many output tokens and had higher cost per task. The Sonnet evaluation used a pre-release build with a structured-output bug that Anthropic said was fixed for public release. These are vendor claims and external benchmark results, not local AFD performance measurements or a cross-harness cost ranking. Recheck availability and pricing before using them for budgets.
