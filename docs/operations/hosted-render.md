# Disposable Render controls for AFD #362

Status: local preparation only. No Render service, disk, credential, identity, or paid resource has been created by this work. The [verification round](hosted-verification-round.md) proposes a $10 maximum incremental spend for 48 hours; it does not authorize provisioning. Keep both services stopped/deleted within an approved window and retain the exact pre-create quote and billing readback.

The custom [Blueprint](../../scripts/hosted/render.yaml) defines two independent paid `0.5c-512mb` web services, each with one instance and its own 1 GB SQLite disk at `/var/data`. H1 uses Node 24, the repository-root pinned pnpm install/build, `cd packages/auth && node hosted/better-auth/serve.mjs`, public `/harness/info` readiness, and the platform `PORT`. H3 uses Node 24, `node packages/local-db/hosted/durable-rest-server.mjs`, `AFD_FIXTURE_PORT=10000`, and TCP readiness; its `/api/v1/health` requires bearer authentication. Automatic deploys are off. Render's generated HTTPS domains and the H1 Google callback must be entered after resource creation; no provider secrets are in the Blueprint.

Validate the YAML with `render blueprints validate scripts/hosted/render.yaml` when the Render CLI is available. This validation sends the Blueprint to Render and is therefore an operator step after authorization, not part of the local preparation. In the Render dashboard, select this exact custom Blueprint path and reviewed Git commit. The H1 app/callback/return URLs are prompted before the generated domain is known; enter the planned `onrender.com` origin, then compare it with the actual service URL and correct any mismatch before an evidence run. After the first sync, disable Blueprint automatic sync as well as service auto-deploy. The service's initial linked branch is not source proof: manually deploy the exact reviewed SHA, then read the live deploy's `commit.id` through the provider API. The self-reported H1 `AFD_BA_REVISION` and H3 `AFD_TEST_HTTP_APP_REVISION` must agree with that independent read.

Copy [the ledger template](../../scripts/hosted/render-ledger.example.json) to a private local path outside the repo. Record the exact run ID, reviewed 40-character SHA, Render owner and Blueprint IDs, both service and disk IDs and creation timestamps. Mark `dedicatedOwnershipVerified` and each role's `dedicated` true only after matching the dedicated resources to this run in Render. The helper takes an immutable copy of this ledger per command and checks the Blueprint path, `autoSync=false`, and a settled `in_sync` or `paused` status; provider service name, owner, creation timestamp, repository, auto-deploy state, plan, instance count, start/health settings; disk size/mount/owner and sole attachment; and one live deploy at the reviewed SHA before routine operations. Any other pending deploy, source change, role mismatch, or unrecognized resource stops the operation. Deploy IDs must match Render's `dep-` format before appearing in receipts. It does not read environment values or log raw API responses.

Run commands from the repository root with Node 24. The operator API key belongs only in the local process environment as `RENDER_API_KEY`; it must never be passed on argv, entered in a fixture, or retained in receipts. `doctor`, dry-run mutation, and `restart-command` do not contact Render. `status` performs provider reads. Mutations require `--apply` and a dedicated ownership ledger.

```sh
node scripts/hosted/render-control.mjs doctor --role=h1 --ledger=/private/path/afd362-ledger.json
node scripts/hosted/render-control.mjs status --role=h1 --ledger=/private/path/afd362-ledger.json
node scripts/hosted/render-control.mjs restart --role=h1 --ledger=/private/path/afd362-ledger.json
node scripts/hosted/render-control.mjs restart-command --role=h1 --ledger=/private/path/afd362-ledger.json
```

The final command prints a JSON argv array suitable for **local** `AFD_BA_RESTART_COMMAND`. It includes `--apply`, the exact H1 role and ledger path, but never the API key. The H1 runner must inherit the local key from its environment. The deployed H1 server's placeholder `AFD_BA_RESTART_COMMAND` is never executed there.

After spend authorization and provider preflight, `restart`, `suspend`, and `resume` with `--apply` issue only the exact role's Render API mutation, then poll within one shared 80-second deadline. That leaves ten seconds for the H1 runner's 90-second subprocess cap. A restart receipt includes the prior/new provider deploy IDs and time; the H1/H3 fixture must separately prove a new process instance and persisted session/store. `suspend` must be followed by the H3 managed-edge HTTP 503 assertion with the same run ID; `resume` requires a subsequent authenticated health read. A provider state or deploy receipt alone does not close either lane.

After H1 synthetic auth data and H3 deterministic records are removed and independently read back, set the role's `recordCleanupVerified` true in the private ledger. `cleanup --role=h1 --ledger=... --records-cleaned --apply` deletes only that role's exact disk and service IDs and requires both GETs to return 404 plus an empty service-filtered disk list. If an earlier attempt deleted only one resource, a retry independently checks the surviving service's owner, shape and live source or the surviving disk's exact ID, creation time, bound service ID, size and mount before deleting it. Only an exact 404 counts as absence. Failed and partial attempts emit a redacted JSON receipt with stage and known resource states and exit nonzero; an uncertain state requires provider inspection before retry. The helper deliberately does not delete the project, Google OAuth client, synthetic identity, or local secret material. Those are separate exact-resource cleanup receipts in the verification round.

The helper makes requests only to `https://api.render.com/v1/`, rejects redirects, does not accept an API-base override, limits JSON bodies to 256 KiB under the request deadline, and emits allowlisted JSON receipts. Provider errors are reduced to a status code, with no response body, token, header, or environment value. The local test suite injects a mock `fetch`; it cannot establish that a particular Render account has the proposed plan or that the Blueprint deploys successfully. Keep H1/H3 external evidence **not run** until exact-candidate CI, approved spend, provider deployment, browser/REST assertions, and cleanup are complete.
