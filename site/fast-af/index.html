No component calls a command. A field says the person typed, a checkbox says it was ticked, and the application turns that into a command, the same one an agent or the command line would call. So the components stay reusable and the commands stay in one place.

Fig. 03The runtime

FAST underneath.
And what FAST-AF adds.

The runtime is a fork of Microsoft's FAST Element. Templates, bindings, attributes and styles are FAST's, unchanged, so what you know about FAST is true here. FAST-AF adds two things an application built for agents needs, and keeps taking FAST's releases.

Where it comes from

FAST

Microsoft's open-source library for building web components on the browser's own standards. Jason Falk co-created FAST and later created AFD. FAST-AF is what the two have in common. It is an independent fork of FAST, not affiliated with or endorsed by Microsoft.

fast.design microsoft/fast
From FAST

What FAST gives every component.

A component is an HTML tag.
FAST builds on the browser's own custom elements and shadow DOM, so a component works in any framework, or with none.
Only what changed is updated.
A template knows which value each binding reads. When a value changes, FAST writes to that one place. There is no virtual DOM, and nothing is rendered again.
It is small.

Added, 1

A registry of its own, all the way down.

A browser can give one part of a page its own list of custom elements, so two versions of a component, or two teams' components with the same name, can share a page. FAST-AF creates everything a component's template renders in that component's registry.

A component you can ask.

And how it is known.

An agent writing a page with these components reads a record for each one it uses: what it is for, its attributes, slots and events, examples that work, and the rules that apply. Every fact says where it came from, so the agent knows what to trust.
