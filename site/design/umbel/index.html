Agent-First Design / Umbel In development, not released

Umbel

An MCP server for your repo.
Every answer names its source.

Umbel is where a repository's agents look things up before they act: how to use a component, what the team decided, what they learned last time. Each kind of answer is a plugin you choose, and every answer names its source.

Read a real answer Where it stands
Content, not commands
Everything it returns is marked as documentation to read. None of it can give an agent an order or a permission.
People approve what lasts
An agent can propose a change to shared knowledge. Only a person, at a terminal, can accept it.
You choose the plugins
Briefs, knowledge and memory each come as a plugin. Use the ones that ship with it, or add your own.

Read itThis is Umbel's answer about the bar from the Specimen page, word for word. Point at a note to see the lines it is about.

  1. It says what it is

    The first two lines tell the agent this is a library's documentation. It is not an instruction and gives no permission.

  2. It names its source

    The library, its package version and a digest of the files it read. This page is recomputing that digest from the files.

  3. Each part says how it is known

    Observed, verified or authored, exactly as Specimen marked each fact.

  4. The lesson travelled

    The line about disabled is the bug Specimen caught in this bar. The next agent reads it before it writes.

  5. It says what it left out

    The CSS properties were left out of a brief. It names the call that returns them.

Fig. 04The approval

Agents propose.
People approve.

Shared knowledge changes one way. An agent writes a proposal with its reason and its evidence, and nothing changes. A person reads the change at a terminal and decides.

  1. Step 1

    An agent proposes

    A new document, an update or a retirement, with a rationale and evidence. It is stored and changes nothing.

  2. Step 2

    A person reads it

    Before any prompt, Umbel shows the proposal's change, its flags and where its evidence came from.

  3. Step 3

    A person decides

    At a terminal, asked twice. It cannot be done by an agent, over MCP, or with a flag that says yes.

  4. Step 4

    Everyone can find it

    The approved text turns up in the next search, labelled as content, with its source.

This figure is described, not run: approving needs a person at a terminal, which is the point.

Fig. 05The two stores

Memory fades.
Knowledge is approved.

What an agent picks up along the way and what a team has agreed are different things, so Umbel keeps them apart and treats them differently.

Memory

What an agent learned

An agent writes it as it works. It is private unless shared, it never counts as verified, and it expires. An old belief is closed with a reason, not overwritten.

What settles moves up

A memory left unchanged for a week and seen in at least two sessions is drafted as a proposal. No model is involved, and a person still approves it.

Knowledge

What the team agreed

It changes only by proposal, and a person approves each change. A search returns only what the person asking is allowed to read.

Fig. 06The work

What an agent
can ask it.

Each of these is a plugin. Turn on the ones your repo needs. None is required, and your repo's own commands can sit beside them.

  • How do I use this component?

    A brief on every component a page uses, from the pack Specimen builds.

    components-brief

  • What did the team decide?

    Search over the team's documents and code. Each hit carries its source and whether it has been verified.

    knowledge-search

  • What did I learn last time?

    Its own notes from earlier sessions, ranked for the task. Nothing in memory counts as verified.

    memory-recall

  • What should I know before I start?

    One bundle sized to fit a session: verified knowledge first, then memory a person confirmed, and a note of what was left out.

    context-bundle

  • Should this be written down?

    A proposal to add or change shared knowledge, for a person to approve.

    knowledge-propose

It is not released yet.

Umbel builds from source and runs on your own machine. There is no package to install and no hosted service. The dev side shows a real run and how to build it.

The host, its plugins and a real run
Status

In development. The host, briefs on components, knowledge, memory and the step from one to the other are built and tested. Signing in to a hosted Umbel and other places to store its data are still in progress. Until then, who may read what is exact only when Umbel is built into another program.
