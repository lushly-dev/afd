Violet

A design token engine.
Every change is a command.

Violet keeps a design system's tokens on one tree, where each theme stores only what it changes. 34 commands read and change that tree, and the CLI, the MCP server and your own code all call the same ones.

Fig. 03The layers

Five packages, so you take
only the layer you need.

The engine needs zod and nothing else, and it knows nothing about AFD. The command layer sits on the engine. The command line and the server sit on the commands. Depend on the lowest layer that does your job.

Endpoints

violet-cli

The violet binary: export, compare, CI setup, any command by name.

violet-server

The violet-mcp binary: an MCP server and a local REST API. Every command is a tool except validate and doctor, which stay in the CLI.

Integration

violet-afd

The command registry and 34 commands. Each takes validated input and returns a CommandResult.

Foundation

violet-core

Storage, inheritance resolution, export to nine formats, rules and the CSS value validators.

violet-runtime

The browser SDK: apply a node's tokens as custom properties and switch themes at runtime.

05
Fig. 05The guard

A token can't
smuggle CSS.

Agents write tokens now, and a token ends up in a stylesheet. Before a page draws a value, pass it through a validator. It returns a rebuilt, safe value or null. It never hands the input back.

It is an allow-list, not a filter: what it doesn't recognise is refused, including url(), var() and named colours. The functions live in @lushly-dev/violet-core/css, which imports nothing, so a page can load them alone.

Fig. 06The store

Keep the tree
where it suits you.

Four places to keep it

Files
DTCG JSON in your repo, one node per file. Nothing to host.
SQLite
The command line's default, in ~/.violet/violet.db.
Postgres or Neon
One shared tree for a team, behind the REST API.
Memory
For tests and workers. It is what this page runs on.

Three workflows from one command

tokens-validate.yml
Checks the tokens and their rules on every pull request.
tokens-release.yml
Builds and releases the exports when you push a tokens-v* tag.
tokens-sync.yml
Fetches exports from a hosted Violet API instead of local files.

Status

Preview. All five packages are on npm at 0.3.0-preview.0, under the preview tag, and share one version. SQLite needs the optional better-sqlite3 package; memory and files need nothing native. The hosted API, the web editor and the Figma plugin are not released yet.
