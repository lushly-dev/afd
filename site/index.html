Agent-First Development

Open source, MIT

Commands are the product.

Agent-First Development is a way of building software where every feature is a command first. The UI, the CLI and an AI agent all call the same commands. It is about software agents can use, not agents writing your code.

See it in action Build with AFD

npm install @lushly-dev/afd-server @lushly-dev/afd-cli zod

      A BRIEF FOR YOUR CODING AGENT
      Build the capability.
      Prove the job works.
      Then design the interface.

      A coding agent can implement a typed command, call it from the terminal and verify the result before a single component exists. The UI comes after the behavior is real.

      Read the workflow
      1. 01

        Define the contract.

        todo-create takes a title and priority, returns a structured result, and rejects missing input.

      2. 02

        Exercise both paths.

        Call the command with an empty title, then a valid one. Verify the error is actionable and the task is created.

      3. 03

        Test the whole job.

        Create a task, list it, check the outcome. A scenario tests the user's goal across commands.

      4. 04

        Give it a surface.

        Connect the form to the proven command. Keep the rules in the command layer, not in the component.

      The AFD family

      The same rule,
      one layer up.

      AFD started as a method and a set of libraries. The projects around them take the same idea to components, design tokens, agent tooling and whole applications. All of them live in one repository, arranged here by what you want to do.
