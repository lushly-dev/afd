    Fig. 03Design for the agent

    Access isn't enough.
    Agents need good UX.

    A person gets labels, feedback and a chance to change their mind. An agent deserves the same care in its command contract.

    Make intent legible.
    Named capabilities, typed inputs and explicit prerequisites.
    Return more than data.
    Reasoning, warnings and a useful next step when something fails.
    Keep people in control.
    Confirm consequential actions. Offer undo where possible. Say when it isn't.

    → A person discovers what an app can do by looking at its menus. An agent reads the contract.

    Know what a command takes, what it does and whether it changes state before calling it.

    A BRIEF FOR YOUR CODING AGENT
    Build the capability.
    Prove the job works.
    Then design the interface.

    A coding agent can implement a typed command, call it from the terminal and verify the result before a single component exists. The UI comes after the behavior is real.

    Read the AFD skill
    1. 01

      Define the contract.

      todo-create takes a title and priority, returns a structured result, and rejects missing input.

    2. 02

      Exercise both paths.

      Call the command with an empty title, then a valid one. Verify the error is actionable and the task is created.

    3. 03

      Test the whole job.

      Create a task, list it, check the outcome. A scenario tests the user's goal across commands.

    4. 04

      Give it a surface.

      Connect the form to the proven command. Keep the rules in the command layer, not in the component.

    Don't take the manifesto on faith.
