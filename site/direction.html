02 / The workflow

Build the part
that lasts.

Define it. Prove it. Then put
any interface on top.

commands/create.tsTypeScript
import { defineCommand, success } from '@lushly-dev/afd-server';
import { z } from 'zod';

export const createTodo = defineCommand({
  name: 'todo-create',
  description: 'Create a todo',
  expose: { mcp: true },
  mutation: true,
  input: z.object({ title: z.string().min(1) }),

  async handler({ title }) {
    const todo = await store.create({ title });
    return success(todo, {
      reasoning: `Created "${title}"`,
      confidence: 1,
    });
  },
});

Connect the handler to your own store or service.

Illustrative output. The command can be tested before the UI exists.

app.tsSurface
import { createClient } from '@lushly-dev/afd-client';

const client = createClient({ url: '/sse' });

// The same call, behind any interface.
const result = await client.call('todo-create', {
  title: 'Ship the website',
});

if (result.success) {
  renderTodo(result.data);
} else {
  showError(result.error.message,
    result.error.suggestion);
}

Your component handles presentation. The command handles the work.

03 / An interface for agents

Give the agent
a way forward.

Good UX doesn’t stop at the screen.
A result can explain what happened,
why it happened, and what to do next. 

{
  "success": true,
  "data": { "id": "todo-8f2c", "title": "Ship the website" },
  "reasoning": "Created the task with high priority",
  "confidence": 1
}

THE AGENT CAN SAY“Added ‘Ship the website’ with high priority.” 

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "A title is required",
    "suggestion": "Provide a title, such as Ship the website",
    "retryable": false
  }
}

THE AGENT CAN ASK“What should I call the task?”

01

Reasoning, confidence, and warnings make context explicit. Permission still comes from your application.
