# Changelog

All notable changes to afd-cpp are documented here. The package is versioned independently of the npm packages (proposal D11) and is released with tags of the form `cpp-vX.Y.Z`.

## [Unreleased]

### Changed

- **`CONFIRMATION_REQUIRED` is listed with `retryable` unset (varies)** in the error catalog, instead of `false`, matching `spec/error-codes.md` ([#2010](https://github.com/lushly-dev/afd/issues/2010)). A relay's pending-list refusal is retryable; `afd::mcp_stdio` has no relay, so no C++ code path changes.
- **Breaking (ABI):** `CommandError` and `ErrorOptions` gained `recovery`, between `retryable` and `details`. Designated initializers are unaffected; positional aggregate initialization that sets `details` must add the new field.
- **Breaking (behaviour): the journal honours `secret`, which changes what it records** ([`spec/journal.md`](../../spec/journal.md)): a `DirectClient`'s own journal middleware, which cannot read the declaration, now records no call without `redact`, and an unrecorded secret call inside a recorded one leaves the parent's tape marked `truncated`.
- **Breaking (ABI):** `CommandDefinition` gained `secret`, between `handoff_protocol` and `examples`, and `JournalMiddlewareOptions::redact` is now an `afd::JournalRedact` instead of a `std::function`, and `Clock` and `RandomSource` gained an internal virtual `journal_tape()` (do not override it). Designated initializers and a one-argument `redact` lambda or `std::function` compile unchanged, and `options.redact != nullptr` and `bool(options.redact)` still test it; binary consumers must rebuild. `secret` is an `afd::StrictBool`, which accepts only a `bool`.
- **ABI:** `CommandContext` gained internal `default_timeout_ms` and `deadline_armed` fields and `StdioServerOptions` gained `default_timeout_ms` (appended after existing fields); binary consumers must rebuild against matching headers and library.
- **ABI:** `CommandContext` gained the internal `caller_allow` field, appended last: `DirectClient` sets it from `DirectClientOptions::allow` so the registry's suggestions and recoveries name only commands that list admits. Binary consumers must rebuild.
- **The default MCP server instructions say what `error.recovery` is** ([`spec/tool-strategies.md`](../../spec/tool-strategies.md), "`server/discover` instructions"): the first sentence is now "`<name>` is an AFD server. Every tool returns a CommandResult as JSON text: { success, data, error: { code, message, suggestion, recovery } }; follow error.suggestion to recover. When error.recovery is present, it is the same step in a form a program can follow."
- **`COMMAND_NOT_IN_CONTEXT` and `COMMAND_NOT_FOUND` name only what a `DirectClient`'s `allow` list admits.** A command the list refuses is no longer offered as a "did you mean" match, among the commands exposed to the surface, or as `afd-context-list` in the not-in-context suggestion, which then names the command's contexts instead (`spec/recovery.md`, rule 2).

### Added

- **`error_codes::IDEMPOTENCY_KEY_REUSED`, `IDEMPOTENCY_IN_PROGRESS` and `OUTCOME_UNKNOWN`**, in the shared catalog's new `idempotency` profile (`spec/error-codes.md`); `error_code_catalog` has 53 entries. No C++ engine sends them yet: the idempotency step is tracked in [#2676](https://github.com/lushly-dev/afd/issues/2676).
- **The shared idempotency key definitions** (`afd/idempotency.hpp`, `spec/idempotency.md`), as TypeScript's: `afd_idempotency_key_meta_key`, `IdempotencySupport` and `is_idempotency_support`, `is_idempotency_key` (K2's form), `derive_idempotency_key` with `IdempotencyRequestKind` (K4) and `invalid_idempotency_key_error`. The engine does not use them yet (#2676).
- **Engine errors carry the recovery `spec/recovery.md`'s "Engine errors" table gives**, beside an unchanged `suggestion` and `retryable`; a batch item or pipeline step that fails with one carries the same recovery.
  - **Lookup and exposure:** `COMMAND_NOT_FOUND` is `call` `afd-discover` on the MCP server, `call` `afd-help` in process when the caller can call it (registered, exposed to its surface, in its context and admitted by its client's `allow` list), and none otherwise; the suggestion and the recovery come from the same decision. A grouped tool's unknown action and `afd-detail`'s per-entry not-found carry none. `COMMAND_NOT_EXPOSED` and `CALL_NOT_GRANTED` (`call_not_granted()`) are `external`. `UNKNOWN_TOOL` and `COMMAND_NOT_ALLOWED` carry none.
  - **Contexts:** `COMMAND_NOT_IN_CONTEXT` is `call` `afd-context-list` when the caller can call it, by the same test as its suggestion, and none otherwise; its suggestion adds "or afd-context-enter to switch" only when the caller can call `afd-context-enter` too. `afd-context-enter`'s `CONTEXT_NOT_FOUND` is `call` `afd-context-list`, and its `CONTEXT_DEPTH_EXCEEDED` is `call` `afd-context-exit` with `thenRetry`, only when the caller's `DirectClient` `allow` list admits that command; otherwise the suggestion drops the command ("Leave a context before entering another" for the depth) and there is no recovery.
  - **Rate limits:** `create_rate_limit_middleware`'s "Too many requests" is `retry` with `afterMs` the same whole number of seconds its suggestion gives, times 1000; "client capacity reached" is `retry`. `rate_limit_error()` is `retry`, with `afterMs` its seconds × 1000, rounded up, when it is given the wait. The other error helpers set none.
  - **Confirmations:** `CONFIRMATION_REQUIRED` (asked, unanswered or refused for want of elicitation) is `external`; `CONFIRMATION_DECLINED` is `stop`.
  - **Approvals:** `APPROVAL_REQUIRED` is `stop` when the user declined (`reason: "declined"`, single call or up front) or a `DirectClient`'s `on_approval_needed` returned `false`; none when the caller reshapes the call (`input-not-known`, `too-many-approvals`, or a gated command the suggestion says to call on its own); and `external` otherwise (a person must approve, the hold is unanswered, or a token was rejected). `APPROVAL_UNAVAILABLE` is `external` for `no-approval-step` and `admission-mismatch` and none for `input-not-canonical`.
  - **Tests:** `tests/dispatch_vectors_test.cpp` and `tests/tool_strategies_vectors_test.cpp` compare `expect.recovery` and `expected.recovery` (`null`: no recovery, absent on the wire), and the dispatch registry surface registers the context commands as plain commands (`setup.contextCommands: "plain"`). `tests/app_calls_vectors_test.cpp` compares the whole refusal, recovery included. The rows no shared vector reaches are pinned in the registry, result, middleware, contexts, DirectClient, approval and MCP tests.
- **`secret` commands in the journal** ([`spec/command-metadata.md`](../../spec/command-metadata.md#fields), [`spec/journal.md`](../../spec/journal.md)): a command that takes or returns a secret sets `CommandDefinition::secret = true`, and `create_journal_middleware` never records a call to it unless it was given `redact`, whatever `filter` says. The recorder reads the declaration from the command `CommandRegistry::execute` runs, never from the name, and `redact` may take a second argument, `const afd::JournalRedactInfo&`, whose `secret` is `true`, `false`, or unset outside the registry's execution (a `DirectClient`'s own middleware, a direct call). A secret call reads off a recording parent's tape, which is marked `truncated`; a recorded one keeps its reads on its own entry. The default `filter` still skips `auth-*`. `secret` is an `afd::StrictBool`, so the non-boolean refusal TypeScript makes at definition is a compile error here, in an initializer and in an assignment. The declaration is read only while the call runs, so a kept copy of a finished call's context reads as unknown, and each recording clock and random source names its own tape, so a secret call given a fresh context that carries them stays off it too. `tests/journal_secret_test.cpp` mirrors the TypeScript tests.
- **Structured recovery on `CommandError`** ([`spec/recovery.md`](../../spec/recovery.md)): `CommandError::recovery` and `ErrorOptions::recovery` hold an `afd::Recovery`, the step the `suggestion` describes in a form a program can follow and a test can check. `RecoveryKind` is `call`, `fix_input` (`fix-input` on the wire), `retry`, `external` or `stop`; `Recovery` carries `command`, `input`, `needs`, `then_retry` and `after_ms`, written as camelCase with unset fields omitted. `recovery_kind_name`, `parse_recovery_kind` and `recovery_kinds` (TypeScript's `RECOVERY_KINDS`) map kinds to their wire names.
  - **Rules:** `Recovery::validate()` names the first `$defs/recovery` rule a value breaks: each field on its kinds (rule 4), a non-empty `command` for `call`, an `after_ms` of at least 0, an `input` object with at least one member and no `confirm` (rule 5), a `needs` of at least one distinct, non-empty name, and `input` or `needs` on `fix-input`. It does not check the error-level rules that tie `retry` and `stop` to `retryable`.
  - **Construction:** `Recovery` is an aggregate built with designated initializers, so a value that breaks the rules can be built. It never reaches the wire: `create_error` and `error` leave a recovery that fails `validate()` off the error, and `to_json` of a `CommandError` omits one set on the field directly.
  - **Reading:** `Recovery::from_json` and `is_command_recovery` accept exactly the values that match `$defs/recovery`. They refuse a non-object, an unknown kind or member, a `null` member, a member of the wrong JSON type (nothing is coerced, so `"30000"` and `true` are not an `afterMs`) and any value `validate()` refuses. A whole number with a zero fraction, such as `30000.0`, is read as that integer. An `afterMs` above 2^53 − 1, the schema's maximum, is refused, as in every language. `CommandError::from_json` reads leniently (rule 7): a recovery that does not match is read as absent, on the error and on each `cause`, and the rest of the error is kept, `suggestion` included. It does not enforce the `retryable` rules.
  - **Tests:** `tests/recovery_vectors_test.cpp` runs all three lists of `spec/vectors/recovery.json` against `spec/schema/error.json`: each `valid` case round-trips unchanged, the `normalizes` case and each `invalid` case read and write back to exactly their `readsAs`. The test schema validator gained `minProperties` and `minItems`, and fails the test outright on a keyword it does not implement or a `$ref` it cannot resolve, checked for every schema when they are loaded, instead of reporting an ordinary validation failure that a `not`, `if` or `anyOf` would invert.
- **Registry cancellation, per-command deadlines, and `StdioServerOptions::default_timeout_ms`** (`spec/execution-controls.md`, [#1766](https://github.com/lushly-dev/afd/issues/1766)): `CommandRegistry::execute` now checks `context.cancellation` after validation before entering middleware and again immediately before the handler (returning `COMMAND_CANCELLED` with `retryable: false`), and enforces `context.timeout_ms` via a child `CancellationSource` and late-finish `TIMEOUT`. `StdioServer::serve` skips `handle` for requests cancelled while waiting in the queue so their handlers never run, and `StdioServerOptions::default_timeout_ms` (default `default_command_timeout_ms = 30000.0`, disable with `0` or `std::nullopt`) applies a server-level per-command deadline. `tests/execution_controls_vectors_test.cpp` now passes every case in `spec/vectors/execution-controls.json` with no remaining C++ gaps.

### Fixed

- **Behaviour change: `create_retry_middleware` no longer repeats a mutation** ([#2673](https://github.com/lushly-dev/afd/issues/2673)). It used to retry any command whose failure code was `TRANSIENT_ERROR` or `TIMEOUT`, so a handler that returned `TIMEOUT` after a downstream write could have that write applied twice. A command declaring `mutation = true` now runs once and its failure is returned. The middleware reads the declaration from the command the registry runs, for a `next` the registry built (as the journal reads `secret`), never from its name; outside the registry it counts the call as a mutation. Set the new `RetryOptions::retry_mutations` (default `false`) to restore the old behaviour, and only when every mutation it wraps is safe to repeat. **ABI:** `RetryOptions` gained `retry_mutations`, appended after `sleep`; designated and positional initializers compile unchanged, and binary consumers must rebuild.

- **The journal reads `secret` only from the registry's own chain** ([`spec/journal.md`](../../spec/journal.md)): the declaration was readable by any recorder on the call's context while `CommandRegistry::execute` ran, so a journal middleware a handler ran itself on its own context under the command's name, at once or kept and run later in the call, read the outer command's declaration as its own and recorded what it was given. The recorder now reads the declaration only when the `next` it was handed is one the registry built for the call's middleware chain (or one `compose_middleware` built under such a `next`); any other recorder reads unknown, so it records nothing without `redact`, and `redact` is told `secret` is unset. Such a call, recorded with `redact`, also reads off its parent's tape, which is marked `truncated`, as a secret call does. Binding the read to the continuation rather than to timing keeps it right when a middleware calls `next` again, as a retry or from inside the handler. Recording by the registry's own middleware is unchanged.
- **Iterative JSON copy on schema pass-through branches** ([#2404](https://github.com/lushly-dev/afd/issues/2404)): `CompiledSchema::validate` now copies pass-through subtrees (boolean `true`, untyped `{}`, arrays without `items`, open objects, `additionalProperties: true`, and defaults) iteratively on the heap instead of invoking `nlohmann::json`'s recursive copy constructor, preventing stack overflow on Emscripten's 64 KiB Wasm stack.
- **Full single-TU unity build symbol collisions** ([#2225](https://github.com/lushly-dev/afd/issues/2225)): deduplicated `max_safe_integer`, `examples_json`, `round2`, and `max_timeout_ms` into `src/detail/json_io.hpp` so all `afd` and `afd_mcp_stdio` sources compile cleanly under `-DCMAKE_UNITY_BUILD=ON -DCMAKE_UNITY_BUILD_BATCH_SIZE=64 -DAFD_WARNINGS_AS_ERRORS=ON`.

## [0.3.0] - 2026-11-24

Implements AFD contract `1.0-rc`.

### Changed

- **Breaking (ABI & exhaustive `switch`):** binary consumers must rebuild against matching headers and library:
  - `CommandContext` gained 12 fields (`direct_approval`, `mcp_approval_relay`, `up_front_approval`, `context_scope`, `remote`, `tool_strategy`, `first_class_tools`, `journaled_fields`, `approval_admission`, `output_budget_ask`, `output_budget`, `output_budget_meta_ask`), `CommandDefinition` gained `title`, `output_budget`, `tool_meta` and `advertised_input_schema`, option/record structs (`CommandRegistryOptions`, `ExecutorOptions`, `ExposeOptions`, `ValidationFailure`, `JournalRecord`, `ApprovalMiddlewareOptions`, `DirectClientOptions`, `ReplayJournalOptions`) grew, and `CommandRegistry`'s private layout changed.
  - `CompiledSchema::validate` gained a defaulted `max_issues` parameter and `create_context_digest` gained defaulted `journaled` and `omitted` parameters (source-compatible, ABI-breaking).
  - `enum class Interface` gained `apps` (an exhaustive `switch` built with `-Werror=switch` needs a case or `default`).
- **Breaking: a `$ref` outside the subset fails at compile** ([#1910](https://github.com/lushly-dev/afd/issues/1910); `spec/validation.md`). The subset is `#`, `#/$defs/<name>` and `#/definitions/<name>`, as in Rust. Before, any local pointer was followed, such as `#/$defs/A/properties/x`. A pointer into a nested `$id` subschema then resolved that subschema's own references against the wrong resource.
  - **Every `$ref` is checked:** a `$ref` inside a definition nothing references is now checked too, as Python and Rust check it.
  - **Escapes:** `~0` in a definition name is decoded once, so `#/$defs/a~00` names `a~0`. Before, it named `a~`.
- **Breaking: `resolve_variables` error type is now `ResolutionLimitError` and pipeline step inputs are bounded** ([#1722](https://github.com/lushly-dev/afd/issues/1722); `spec/pipeline-variables.md`, "Limits"):
  - **Before:** a step input that repeated a reference to a large value copied it in full each time, and a referenced value was copied at any depth; only the template's depth was checked, before any step ran.
  - **Now:** `resolve_variables` fails with `ResolutionLimitError` (naming the `ResolutionLimit` exceeded) when a value copied into the input nests deeper than 64 levels, or the resolved input exceeds `max_resolved_nodes` (100,000) values or `max_resolved_chars` (16 MiB) string and key characters, counted in UTF-16 code units. Only a repeated expansion of the same referenced value is charged for its contents.
  - **Pipeline engine:** the step fails with `VALIDATION_ERROR` (`retryable: false`, `details: {"stepIndex", "limit"}`) without running its command. A resolution failure was reported as `INTERNAL_ERROR`, though no input the engine accepted reached it.
  - **References:** they are now followed through pointers into the context, so a lookup no longer copies every value along its path.
- **Breaking: `ApprovalMiddlewareOptions::include_token` is now `std::optional<bool>`** (`spec/command-metadata.md`, "Approvals", rule 6; [#1665](https://github.com/lushly-dev/afd/issues/1665)). Left unset, it includes `details.approvalToken` except on calls whose `context.surface` is MCP, as TypeScript, Python and Rust do. An MCP agent therefore never holds the token, and the host gets it through `on_approval_required`. Over MCP, a held call's suggestion now says how the client can be asked: call the command on its own, or from a client that supports form elicitation. Set `include_token = true` to keep the old behaviour.
- **Breaking (behaviour): approval policies are enforced by the registry** ([#1886](https://github.com/lushly-dev/afd/issues/1886)); hosts that relied on the old behaviour need to change:
  - A registry without the approval middleware refuses a command whose policy is not `not_required` (`APPROVAL_UNAVAILABLE`): add the middleware, or register the command without its policy.
  - A command missing from `ApprovalMiddlewareOptions::commands` is now held by its own policy.
  - A retry placed after the approval middleware is refused (`admission-mismatch`): middleware that retries or changes the input goes before it. This holds for a command gated only by the middleware's `commands` list too: the middleware marks the call, also when middleware before it calls it under another name, and the registry takes its admission at dispatch.
  - The approval middleware admits only a call one of its own policies (the command's, or its `commands` entry's) may gate, and every approval middleware that ever admitted a call must admit it afresh and match at dispatch, so a second approval middleware that does not gate a command neither re-admits a retry nor replaces the first one's binding. One approval middleware per registry is the supported setup.
  - The approval summary prefers the `confirm_prompt` of the command the registry runs over the `commands` entry's.
  - Replaying a journal of gated commands needs the approval middleware on the replay registry, or the policies removed there.
  - Passing the registry's own definitions in `commands` is now redundant, and a function policy given both ways may be evaluated twice.
  - A call the approval middleware would hold whose input `canonical_json` cannot encode, such as an integer beyond 2^53 − 1, is answered `APPROVAL_UNAVAILABLE` (`retryable: false`, `details.reason` `input-not-canonical`, nobody asked) instead of `COMMAND_EXECUTION_ERROR`. A call whose policy lets it through still runs.
- **Breaking (behaviour): execution controls enforce default batch and validation ceilings** (`spec/execution-controls.md`, [#2131](https://github.com/lushly-dev/afd/issues/2131); see Added): `execute_batch` and `afd-batch` enforce `default_max_batch_size` (`500`) and `default_max_batch_parallelism` (`16`), and schema validation caps reported issues at `default_max_validation_issues` (`100`).
- **Breaking (behaviour): `false` schema issue code and boolean root schema refusal** ([#2047](https://github.com/lushly-dev/afd/issues/2047); `spec/validation.md`): a `false` schema now reports TypeScript's issue for `not: {}` (`invalid_type` with `expected: "never"` and `Invalid input: expected never, received <type>`, instead of `invalid_value` with `Invalid input`), and `CommandRegistry::register_command` refuses a boolean root input schema, which it used to accept.

### Fixed

- `parse_bounded` is linear in input size. Results are unchanged: the outermost container is level 1, and the input is reported too deep or malformed by whichever comes first (#397).

Cancelling the caller, or a `DirectClient::pipe` step passing the pipeline's deadline, now reaches the handler. Only the call's own deadline produces TIMEOUT.
