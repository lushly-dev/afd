### Added

- **Commands can declare `secret=True`** (`spec/command-metadata.md`, `spec/journal.md`) when they take or return a secret, such as a password or an issued token: on `CommandDefinition`, `define_command`, `@server.command`, `SimpleRegistry.command`/`register` and `MockServer.command` (the last two also read it from a `define_command` decoration on the handler). A non-boolean `secret` raises `TypeError` when the command is defined or registered. `create_journal_middleware` never records a call to such a command unless it was given `redact`, whatever its `filter` returns, in `create_server`, `create_direct_registry`, the core `CommandRegistry`, `SimpleRegistry` and `MockServer`: the shared executor binds the declaration of the command each dispatch runs to the continuations it builds for that dispatch's middleware chain (`compose_middleware` passes it on to its own), and the recorder reads it only through the `next` it was handed, while the dispatch runs and on the dispatch's own context, never from the name. It holds across a middleware that moves the rest of the chain to a worker thread; a recorder given a `next` of its own, a handler or another host's chain included, reads unknown. A secret call reads neither of a recording parent's taped sources, and the parent's tape is marked `truncated`; a recorded secret call keeps its reads on its own entry. The default filter still skips `auth-*`. `afd.auth`'s `auth-sign-in`, which takes a password, now declares it.
- **`redact` may receive an `afd.server.JournalRedactInfo`** whose `secret` is `True`, `False` or `None` (when the recorder cannot read the declaration). It is passed as the second argument when the redactor's second positional parameter has no default, or as `info=` when the redactor has a parameter named `info`. Any other redactor, one that takes `*args` or a defaulted second parameter included, is called with the record alone, as before.

### Changed

- **Behaviour change: a journal outside the execution engine records nothing without `redact`.** Where the recorder cannot read a command's `secret` declaration (a `DirectClient`'s own middleware, a direct call of the middleware, another host's middleware chain such as Botcore's `CommandHost`, a chain a handler runs itself, or any recorder run with a `next` the engine did not build), it used to record every call `filter` allowed; it now records a call there only when it was given `redact`.
