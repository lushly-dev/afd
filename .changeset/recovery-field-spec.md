`CommandError` gains an optional `recovery` ([`spec/recovery.md`](https://github.com/lushly-dev/afd/blob/main/spec/recovery.md)): the step a failed command's `suggestion` describes, in a form a program can follow and a test can check. Its `kind` is `call` (a `command` to call next, with optional `input`, `needs` and `thenRetry`), `fix-input` (the failed call's input with `input`'s members replaced and `needs` chosen; at least one of the two set), `retry` (with optional `afterMs`; the error must set `retryable: true`), `external` or `stop` (never `retryable: true`). Producers name only a command the caller can see and call, never put an acknowledgement, approval or credential in `input` (the schema refuses `confirm` there), and never copy untrusted text into a recovery. Consumers read a recovery that does not match `$defs/recovery` as none and keep the rest of the error; a follower passes the same checks as for any call, follows only the error's own recovery, and bounds waits and chains. `spec/schema/error.json` enforces the field rules; `spec/vectors/recovery.json` holds valid, normalized and invalid errors, each invalid one with the error a reader must produce; `spec/wire/result-failure.json` and `batch-result.json` carry a recovery.
