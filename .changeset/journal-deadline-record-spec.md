[`spec/journal.md`](https://github.com/lushly-dev/afd/blob/main/spec/journal.md) now states, per language, what the journal holds for a call whose caller was given a deadline failure (`TIMEOUT`, `BATCH_TIMEOUT` or `PIPELINE_TIMEOUT`), in a new section, "Calls that end at a deadline": TypeScript writes an entry when the handler later settles, holding the handler's result; Python writes none unless the handler catches the cancellation and returns; Rust writes none, since the call's future is dropped; C++ keeps waiting and writes an entry with the handler's result before the caller gets the deadline failure. A batch item or pipeline step that never started has no entry in any language. It also states the cases that are not a plain deadline: TypeScript's and C++'s `COMMAND_CANCELLED` for a deadline that passed before the handler started (recorded only with `recordFailures`), Python's `COMMAND_EXECUTION_ERROR` for a handler that raises on the cancellation, Python's `COMMAND_CANCELLED` when its inner task ended cancelled (no entry), Python's and Rust's `DirectClient` recording a handler that blocked past the client's deadline, where the entry's `timestamp` and `durationMs` are measured from, and that the recorder's own `append` counts against the deadline in TypeScript, Python and C++, and in Rust against every deadline but a command's own. Streams are not covered. [`spec/execution-controls.md`](https://github.com/lushly-dev/afd/blob/main/spec/execution-controls.md) links to it.

Behaviour change: none. Each language has a test that pins the stated behaviour with a barrier the test controls. The differences between languages are listed for the held abandoned-call work (journal seams S4, #2725), not closed here.
