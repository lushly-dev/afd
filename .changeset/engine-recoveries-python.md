### Changed

- **Engine errors carry a recovery** (`spec/recovery.md`, "Engine errors"): the errors the registry, server, tool router, middleware, confirmation and approval steps, context commands and direct client emit now set the structured `error.recovery` the specification's table gives, beside an unchanged `retryable`. `COMMAND_NOT_FOUND` names `afd-discover` (`{kind: "call"}`) only where the caller can call it: over MCP, and from an in-process `server.execute`, which also runs the meta-tools outside the `apps` interface, unless an `allow` list refuses it; its `afd-batch` items agree. Where the caller cannot call `afd-discover`, it names `afd-help` when the caller can call it (`bootstrap=True`) and otherwise ends "Check the command name against the available commands." with no recovery. The core registry and `create_direct_registry` name `afd-help` when the caller can call a registered command by that name, and otherwise keep "List available commands to see valid options" with no recovery. `COMMAND_NOT_IN_CONTEXT` names `afd-context-list` in its suggestion and recovery only when the caller can call it (registered, exposed to its interface, in context, admitted by any `allow` list and shown under its scopes), and adds "or afd-context-enter to switch" only when it can call that too; otherwise it names the command's contexts with no recovery. Only registered commands cross a direct registry's boundary, never the server's built-in context commands, so there a registered `afd-context-list` gives `{kind: "call", command: "afd-context-list"}` and otherwise the suggestion names the contexts. `COMMAND_NOT_EXPOSED`, `CALL_NOT_GRANTED`, `CONFIRMATION_REQUIRED` and an approval a person must give carry `{kind: "external"}`; `CONFIRMATION_DECLINED`, a declined approval and a `DirectClient` whose `on_approval_needed` answers `False` carry `{kind: "stop"}`; a hook that raises or answers anything but a boolean is no longer a decline and leaves the hold as it was, `{kind: "external"}`; `CONTEXT_NOT_FOUND` from `afd-context-enter` now lists the configured contexts ("Available contexts: …."), and names and calls `afd-context-list` when the caller can call it; `CONTEXT_DEPTH_EXCEEDED` says "Call afd-context-exit to leave a context before entering another" and calls `afd-context-exit` with `thenRetry` when the caller can call it, and otherwise says "Leave a context before entering another" with no recovery. The rate limiter sets `{kind: "retry", afterMs}` with the same whole seconds its suggestion gives, and `{kind: "retry"}` at client capacity and at a task limit. A grouped tool's unknown action now says "Use afd-call with the full command name, or list tools to find a valid action.", the text every language uses, instead of naming `afd-discover` and `afd-detail`. A `DirectClient` whose `on_approval_needed` answers `False` now says not to run the call again without asking the user.
- **`rate_limit_error()`** sets `{kind: "retry"}`, with `after_ms` of the given seconds × 1000 rounded up to a whole millisecond when that is a finite wait from 0 to 2^53 − 1, and no `after_ms` otherwise; it never raises. The rate-limit middleware does the same, and a window too long to state (`window_ms=float("inf")`) now refuses with `{kind: "retry"}` instead of raising. The other error helpers set no recovery.
- **The default server instructions** begin "`<name>` is an AFD server. Every tool returns a CommandResult as JSON text: { success, data, error: { code, message, suggestion, recovery } }; follow error.suggestion to recover. When error.recovery is present, it is the same step in a form a program can follow."
