### Breaking changes

- **A handler that returns something other than a `CommandResult` fails the same way on every path** ([#1760](https://github.com/lushly-dev/afd/issues/1760); `spec/error-codes.md`). A single call (`server.execute`, an individual or grouped tool, `afd-call`, an MCP task, and `CommandRegistry.execute`, `DirectClient.call` and the testing `MockServer`, which share the executor) now gets the `INVALID_COMMAND_RESULT` failure (not retryable) that a batch item, pipeline step or stream already got, instead of the raw value passed through with no metadata. A dict with a boolean `success` is still parsed as a result, so `{"success": True, "data": ...}` keeps working. The coerced result is stamped with execution metadata and is what middleware sees, and a middleware that returns a plain value is coerced too. Return `success(...)` or `error(...)` from handlers that returned plain values.
- **`afd[server]` and `afd[client]` require `mcp>=2.3,<2.4`**, capped at the newest minor the full suite has passed on ([#1756](https://github.com/lushly-dev/afd/issues/1756)). Before, any `mcp` 2.x was accepted, though the server relies on SDK internals that a minor release could change. The weekly `Python newest MCP SDK` workflow runs the full suite on the newest 2.x and says when the cap can be widened.
- **Telemetry events from `create_telemetry_middleware` carry `error` as a `CommandError`** ([#1760](https://github.com/lushly-dev/afd/issues/1760)), not a dict. `event.error["code"]` and `event.error.get("code")` still work with a `DeprecationWarning`; read `event.error.code`. `ConsoleTelemetrySink`'s text line is now TypeScript's (`[Telemetry] [trace] todo-create SUCCESS in 150ms (confidence: 0.9) - CODE: message`), and its JSON line is the whole event in camelCase with `_prefix`, for both constructors: it now includes `metadata`, `commandVersion` and, with `include_input=True`, the command's `input`, which the middleware's former sink left out. `ConsoleTelemetrySink(format=...)` refuses anything but `"text"` or `"json"` with `ValueError`.
- **`afd.server.middleware.TelemetryEvent` is now the Pydantic model `afd.core.telemetry.TelemetryEvent`, not a dataclass.** Build it with keyword arguments; positional construction, `dataclasses.asdict()` and `dataclasses.replace()` no longer work (use `model_dump()` and `model_copy(update=...)`). `"code" in event.error` and comparing `event.error` with a dict no longer work; read its attributes.

### Changed

- **One telemetry type** ([#1760](https://github.com/lushly-dev/afd/issues/1760)): `afd.core.telemetry.TelemetryEvent`, `TelemetrySink` and `ConsoleTelemetrySink` are the only ones, exported from `afd`, `afd.core` and `afd.server`. `TelemetryEvent` is a `WireModel`: `to_wire(event)` and `model_dump(by_alias=True)` give camelCase keys (`commandName`, `startedAt`, `durationMs`, `traceId`, ...) as TypeScript's does, and it accepts snake_case names or camelCase keys. `TelemetrySink.record` may return an awaitable. `ConsoleTelemetrySink` takes `format=` as before and `log=`, `json_mode=` and `prefix=` from the middleware's former sink. `is_telemetry_event` accepts the camelCase wire form, and the middleware records the result's metadata in its wire form (camelCase, unset fields left out) instead of a snake_case dump with `None`s.
- **Per-call schema work is cached** ([#1760](https://github.com/lushly-dev/afd/issues/1760)). A Pydantic input model's JSON Schema is generated once per model class (again after `model_rebuild`), not on every call, and the MCP tool list is built once per tool strategy, active context and listed commands, not on every `tools/list`; registering a command or changing those options rebuilds it. `get_tool_definitions()` still returns a copy the caller may change. A registered definition changed in place (its description, schema or contexts) is not seen by `tools/list` until the list is built again; register a new definition instead. `python/benchmarks/per_call_overhead.py` times both.
- **Fewer MCP SDK internals** ([#1756](https://github.com/lushly-dev/afd/issues/1756)). The server no longer registers tools in the SDK's tool manager (`MCPServer._tool_manager`, `Tool`, `FuncMetadata`, `ArgModelBase`): its `call_tool` routes every name itself, and Mcp-Param header validation reads AFD's own tool schemas. The request-state middleware is installed through the public `MCPServer.middleware`, and `InputRequiredResult` is recognised by type, not class name. The internals left (`MCPServer._lowlevel_server`, `Server._request_handlers`, the instance's `get_capabilities`, `MCPServer._tool_input_schema`, `ServerSession._connection`, and AFD's place just before the SDK's `RequestStateBoundary` in the provisional middleware chain) are listed in `afd.server.sdk_internals`, each with a guard test that names it and what breaks. A session without `_connection` now logs one warning instead of silently losing context state between requests.

### Deprecated

- `afd.server.middleware.TelemetryEvent`, `TelemetrySink` and `ConsoleTelemetrySink` are deprecated aliases of the `afd.core.telemetry` names and warn on access. Import them from `afd`, `afd.core` or `afd.server`.
