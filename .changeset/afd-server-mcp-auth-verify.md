`createMcpHandler` and `createMcpServer` take an `auth` option that makes the HTTP server an OAuth 2.1 protected resource, as `spec/authorization.md` M1 to M5 and M7 specify. Every HTTP route (`/mcp`, `/sse`, `/message`, `/rpc`, `/batch`, `/stream`, `/health` and any other path) then needs exactly one bearer token in the `Authorization` header; a missing, malformed or refused token, a token in the query or a form body, or a second header is answered 401 with the exact `WWW-Authenticate` challenge and JSON body, and the RFC 9728 protected-resource metadata is served without authentication at its two well-known paths. stdio, `server.execute()` and in-process registries are unaffected. The scope options (`requiredScopes`, `resolver`, `filterToolsByScope`) are not enforced yet, and passing one throws.

`JwtVerifier` verifies JWT access tokens (RFC 9068) by every M3 rule in order, its own code, with `jose` 6 checking the signature only, through WebCrypto (RS256 to RS512, PS256 to PS512, ES256, ES384 and EdDSA on Ed25519); the audience check is never optional, and `none` and `HS*` are always refused. Its keys come from a `KeySource`, such as `jwksKeySource(document or load)`, which loads the host's JWKS, refetches an unknown `kid` at most once per interval and keeps the last good keys; AFD opens no socket. `createIntrospectionVerifier` checks opaque tokens through the host's RFC 7662 call. The rules are exported too (`extractBearer`, `checkJwsHeader`, `checkKeyFit`, `checkClaims`, `checkIntrospection`, `parseScopeClaim`, `audienceAccepts`, `createProtectedResource`, `createTokenRules`), and the suite loads `spec/authorization.json`'s verification cases.

Commands see the verified `credentials` on their context, never the token: the `Authorization` header is removed before `createContext` runs, which now receives `{ credentials }` as its second argument to map them to an `actor` (by default `{ kind: 'agent', id: <clientId>, onBehalfOf: <subject> }`) and cannot replace them. The credentials are frozen and recognised by `isVerifiedCredentials` until the request ends, so afd-auth's `createAuthMiddleware(adapter, { isVerifiedCredentials })` keeps a token's actor; their debug form redacts all but `issuer` and `expiresAt`. A refused token's rule code goes to `auth.onRefusal`, by default a `console.warn` line, with the issuer's alias and never the token or a claim. `jose` ^6.2.14 is a new dependency, outside the `/define`, `/direct` and `/credentials` entries.
