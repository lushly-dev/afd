### Added

- **`error_codes::IDEMPOTENCY_KEY_REUSED`, `IDEMPOTENCY_IN_PROGRESS` and `OUTCOME_UNKNOWN`**, in the shared catalog's new `idempotency` profile (`spec/error-codes.md`, 53 codes). The registry's idempotency step sends them (below).
- **The shared idempotency key definitions** (`afd::idempotency`, `spec/idempotency.md`), as TypeScript's: `AFD_IDEMPOTENCY_KEY_META_KEY`, `IdempotencySupport` (`Natural`, `Keyed`; `#[non_exhaustive]`) and `is_idempotency_support`, `is_idempotency_key` (K2's form), `derive_idempotency_key` with `IdempotencyRequestKind` (K4) and `invalid_idempotency_key_error`.
- **Idempotency keys: a mutation a caller can safely send twice** ([#2956](https://github.com/lushly-dev/afd/issues/2956), `spec/idempotency.md`). `CommandDefinition::with_idempotency(IdempotencySupport::Natural | Keyed)` sets the new `idempotency` field. `Natural` adds the MCP annotation `idempotentHint: true`, and the value is reported in the tool's `_meta.idempotency`, grouped `_meta.actions`, `afd-detail` and `afd-help` (`full`, the new `CommandInfo::idempotency`). A caller sends a key in `_meta["dev.afd/idempotencyKey"]`, a meta-tool's `meta` argument (a key the context hook sets wins), `CommandContext::with_idempotency_key` (the new public `idempotency_key` field) or `DirectClient::call_with_idempotency_key`. `CommandRegistry::execute` checks its form (1 to 200 of `A-Z a-z 0-9 . _ ~ -`, else `VALIDATION_ERROR` naming the `_meta` key; over MCP before any confirmation) and gives it to the handler. Batch items and pipeline steps run under `<key>:<i>` and `<key>:step:<i>`, and a command a handler runs through the registry starts without the key it was given. The journal records it in the new `JournalEntry::idempotency_key` and `JournalRecord::idempotency_key`, and replay restores it as the engine's.
- **The engine's idempotency step.** `CommandRegistry::set_idempotency(IdempotencyOptions)` adds it (`with_store`, `with_ttl_ms` (default one day), `with_lease_ms` (default 60 s), `with_clock`, `with_callers_identified_by_hook`; `clear_idempotency` removes it), and `check_idempotency_options` checks S8 (`ttl_ms` greater than the default deadline plus `lease_ms`; `set_idempotency` refuses otherwise against the registry's default deadline, and `McpServer::validate` and every way of serving it against the server's). It needs no feature. Between the approval admission check and the handler, it answers a repeat of a `keyed` command's call that carries a key, the same input and the same declared context fields from its store with `metadata.idempotentReplay: true` (`IDEMPOTENT_REPLAY_KEY`). Otherwise it refuses the repeat with `IDEMPOTENCY_KEY_REUSED` (another input), `IDEMPOTENCY_IN_PROGRESS` (still running) or `OUTCOME_UNKNOWN` (the first call returned `TIMEOUT`, panicked, or outlived its lease), scoped to the principal binding middleware left. The engine drops a call at its deadline (S7, `drops`): the reservation stays live until `lease_ms` past the deadline and is never settled after that. A `TIMEOUT` on a call whose key the step reserved carries `recovery: { kind: "retry" }`. An input with no canonical JSON cannot carry a key (`VALIDATION_ERROR`, `reason: "input-not-canonical"`), and a task run is never acted on. `IdempotencyStore` (`async_trait`: `reserve`, `complete`, `release`, `get`, each atomic for its scope) is the interface a host may supply. `InMemoryIdempotencyStore` is the default, for this process only, with `IdempotencyRecord`, `IdempotencyReservation` and the `#[non_exhaustive]` enums `IdempotencyRecordState`, `IdempotencyReserveOutcome` and `IdempotencySettlement`. On the MCP server, an HTTP caller the server cannot tell apart (no `server-auth` credentials, and no hook declared with `with_callers_identified_by_hook`) is refused with `UNAUTHORIZED`, and anonymous stdio connections never share keys. `tests/idempotency_vectors.rs` runs every case of `spec/vectors/idempotency.json` but the other engines' three S7 cases, and Rust leaves its `gaps`.

### Changed

- **The retry middleware follows the declaration** (`spec/idempotency.md`, R1). It repeats a `natural` command, a `keyed` one only when the call carries a key and is not a task run, and any other unless it declares `mutation`. `retry_mutations: true` still restores retrying everything.
- **`idempotency_key` and `idempotencyKey` are reserved context names**, so declaring a context field of either name now fails registration. A key that host code or the context hook sets is validated like a caller's, so a malformed one fails the call with `VALIDATION_ERROR`.
- **A journal entry whose call carried a key** hashes it as a member of `contextDigest`, so its hash differs from a recording made before.
- **New public fields:** `CommandDefinition::idempotency`, `CommandInfo::idempotency`, `JournalEntry::idempotency_key` and `JournalRecord::idempotency_key`. Code that builds one of these with a struct literal adds the field (`None`).
- **The pipeline executor's per-step context** now holds `stepIndex`, the step's 0-based index, beside `traceId`.
