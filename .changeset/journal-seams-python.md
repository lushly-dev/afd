### Added

- **`context.dispatch_id`** (`spec/dispatch.md`, "The dispatch id"), so a host can key a record of its own by the call it describes (#2682). `create_server`, `create_direct_registry`, `create_command_registry` and `SimpleRegistry` give every call an id: 128 bits from `secrets`, as 22 characters of unpadded base64url, never drawn from `context.random` or taken from the caller. Each batch item, pipeline step and command a handler runs through the registry gets its own, and a retry inside the middleware chain keeps it. The engine keeps it, keyed by the context object the call runs on, and `CommandContext.dispatch_id` and `DirectContext.dispatch_id` are read-only properties that look it up (assigning or deleting one raises `AttributeError`), so every middleware, each part of a `compose_middleware`, an app call's `call_grant` and the handler read the same value. Nothing on the object holds it, so copies, pickles, `vars()`, `repr`, results and journal entries never carry it, and a context without `dispatch_id` or `dispatchId` in `extra` hashes to the same context digest as before. A host's own context class that is not an AFD one, a slotted dataclass for instance, runs on a copy whose class adds the property. A `define_command` function called as a plain function is not a dispatch: it reads `None` while it runs, and the caller's context reads its own id again afterwards. The engine calls a decorator a host put around a `define_command` function with `functools.wraps`, which before could be skipped, and `MockServer`'s handlers read the id their middleware reads.
- **`on_approval_accepted(summary, dispatch_id)`** on `create_approval_middleware` (`spec/command-metadata.md`, "The approval summary"), called and awaited when the middleware admits a held call (an approval token, DirectClient's private exchange, `HumanRelay` evidence, an answer over the MCP relay, each gated step of an `afd-batch` or `afd-pipe` approved up front), before the handler. The new `ApprovalSummary` carries `via`, `command`, `input_digest`, `approval_id`, and `issued_at` and `expires_at` when the evidence has them, with `to_dict()` for its JSON; it holds no token, nonce or decision id. A hook that raises fails the call with `COMMAND_EXECUTION_ERROR` before the handler runs, as a raising middleware does, and the evidence stays spent.
- **`approval_id`** on `ApprovalRequest` (what `on_approval_required` is given) and on DirectClient's `DirectApprovalRequest`, keyword-only, the id the call's summary will carry, and `approval_id(key)` to compute it. `ApprovalSummary` and `approval_id` are exported from `afd.server`. `spec/vectors/journal-seams.json` no longer lists Python as a gap; every case runs.

### Breaking changes

- `dispatch_id` and `dispatchId` are reserved context names, as `spec/context-fields.md` requires from the release that sets the id. A declared context field of either name fails at registration (rename the field), and a value a caller or a `context_hook` puts under either name in `context.extra` is removed when the call starts (keep the host's own value under another name). A context whose `extra` held a value under either name hashes to a different context digest, since the name no longer enters `keys`. A dataclass subclass of `CommandContext` or `DirectContext` that declares a `dispatch_id` field fails at construction with `AttributeError` (rename the field). Code that builds an `ApprovalRequest` or a `DirectApprovalRequest` itself, such as a test's fake, now passes `approval_id` as a keyword.
- A context of the host's own class (not `CommandContext` or `DirectContext`) that the engine used to run on as it was, because `with_context_defaults` could not fill it, now runs on a copy whose class adds `dispatch_id`, as TypeScript's engine always copies. A middleware's or handler's writes to it no longer reach the caller's object, `type(context) is HostContext` and a dataclass `==` against the caller's object are false (`isinstance` still holds), and a context that cannot be copied raises `TypeError` instead of running. A slotted dataclass context, which `with_context_defaults` copies, also runs on such a copy.
