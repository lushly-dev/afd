The errors AFD's engines emit carry a `recovery` ([`spec/recovery.md`](https://github.com/lushly-dev/afd/blob/main/spec/recovery.md), "Engine errors"). An unknown command calls `afd-discover` or `afd-help`, and a command outside the active context calls `afd-context-list`, each only when the caller can call it; the suggestion names the same command under the same test. A command not exposed or not granted, a confirmation, an approval a person must give and a missing approval step are `external`. A declined confirmation or approval is `stop`. A rate limit is `retry`, with `afterMs` when the window's end is known. `CONTEXT_NOT_FOUND` calls `afd-context-list`, and `CONTEXT_DEPTH_EXCEEDED` calls `afd-context-exit` and retries. A call the caller must reshape (an up-front approval split, a gated step to call on its own, input that is not canonical JSON) carries none. The default server instructions now read "follow error.suggestion to recover. When error.recovery is present, it is the same step in a form a program can follow." `vectors/dispatch.json`, `tool-strategies.json` and `app-calls.json` pin the recoveries; `dispatch.json`'s registry surface registers the context commands as plain commands.
