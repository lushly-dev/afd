Idempotency keys are specified in a new page, [`spec/idempotency.md`](https://github.com/lushly-dev/afd/blob/main/spec/idempotency.md). A command may declare `idempotency`: `natural` (repeating a call leaves the same state, and the tool reports `idempotentHint: true`) or `keyed` (a repeat is safe with a key). A caller sends a key in `_meta["dev.afd/idempotencyKey"]`, 1 to 200 characters of `A-Z a-z 0-9 . _ ~ -`; the engine validates it and puts it on the command context as `idempotencyKey`, a reserved name, a batch item or pipeline step runs under a key derived from the request's, and a nested call starts without one.

A server may be given an idempotency step that sits between the approval admission check and the handler. For a call that carries a key to a `keyed` command it compares the input and the declared context, answers a repeat from a store for as long as the store remembers the key (a day by default), refuses the key for another input (`IDEMPOTENCY_KEY_REUSED`), tells a concurrent repeat to wait (`IDEMPOTENCY_IN_PROGRESS`), and answers `OUTCOME_UNKNOWN` where an earlier attempt started and nobody can say whether it was applied. The retry middleware repeats a `natural` command, repeats a `keyed` one only when the call carries a key, and repeats any other command unless it declares `mutation: true`; the host's `retryMutations` option restores retrying every command. Where the step acted on a call, its `TIMEOUT` carries a `retry` recovery, and a journal entry records the key in an optional `idempotencyKey` member.

No implementation has any of this yet. A new vector file, [`spec/vectors/idempotency.json`](https://github.com/lushly-dev/afd/blob/main/spec/vectors/idempotency.json), pins it and lists all four languages in its `gaps`; each language loads it and skips every case under its tracking issue. The two new codes are listed in `spec/error-codes.md` under "Specified, not yet in the catalog" and join `vectors/error-codes.json`, with their constants, in the first implementation. `spec/schema/result.json` gains `metadata.idempotentReplay`, which is only ever `true` and only the engine sets.
