# @lushly-dev/violet-afd

## 0.3.0-preview.4

### Patch Changes

- [#2090](https://github.com/lushly-dev/afd/pull/2090) [`4873305`](https://github.com/lushly-dev/afd/commit/4873305c76634295031b109ceefa7a3c017c77e5) Thanks [@Falkicon](https://github.com/Falkicon)! - Harden Violet token writes, sequence allocation and in-memory transactions ([#1957](https://github.com/lushly-dev/afd/issues/1957), [#1958](https://github.com/lushly-dev/afd/issues/1958), [#1973](https://github.com/lushly-dev/afd/issues/1973)):

  - `validateTokenId` now refuses token ids whose dot-separated segments are empty or contain characters outside `[A-Za-z0-9_-]`, in addition to the reserved object-key segments (`__proto__`, `constructor`, `prototype`). `token.add`, `token.override`, `token.copy` (on its target id, including an explicit empty `asTokenId`), `import.json` and `import.tree` (including with `tiers: true`) refuse unsafe ids with `VALIDATION_ERROR` and a suggestion before writing anything; `import.validate` reports them as errors; `export.tree` and the CSS/SCSS exports (`checkCssToken`) refuse legacy unsafe ids already in a store (including empty segments such as `space..m`) while `tokens.resolve`, `token.copy` (with a safe `asTokenId`) and `token.remove` still let callers inspect and clean them up ([#1957](https://github.com/lushly-dev/afd/issues/1957)).
  - `Database.appendOperation` (taking `NewOperationRecord`) allocates a node's next operation sequence atomically with the insert on `MemoryDatabase`, `SQLiteDatabase`, `PostgresDatabase` (locking the node row `FOR UPDATE` and scoping active transactions via `AsyncLocalStorage`) and `OverlayDatabase.stagingView()` (reconciling staged sequences above base operations on read), and every writing command in `violet-afd` uses it so concurrent writes to one node never share a sequence ([#1958](https://github.com/lushly-dev/afd/issues/1958)). Custom `Database` adapters must implement `appendOperation()`; `doctor` checks for it and `import.json` fails closed with `INTERNAL_ERROR` if absent.
  - `MemoryDatabase.transaction()` now snapshots all mutable store collections before running `fn()` and restores them on synchronous throws or async rejections, including nested savepoints, and isolates concurrent top-level transactions and outside writes where `AsyncLocalStorage` is available ([#1973](https://github.com/lushly-dev/afd/issues/1973)).

## 0.3.0-preview.3

### Minor Changes

- [#1942](https://github.com/lushly-dev/afd/pull/1942) [`b536522`](https://github.com/lushly-dev/afd/commit/b5365226a83c75125878a19d4f38e9e973285f7b) Thanks [@Falkicon](https://github.com/Falkicon)! - Violet's commands gain what Violet in Loam's first slice needs ([#1322](https://github.com/lushly-dev/afd/issues/1322) to [#1328](https://github.com/lushly-dev/afd/issues/1328)):

  - `export.tree` writes a tree as DTCG files, one per node with only its own tokens, the inverse of `import.tree`: reading the files back resolves the same, and exporting again gives the same files. A token whose id runs on from another's is written as a dotted key. It refuses subtract, reset and copy operations, which a file cannot hold, and lists in `dropped` the settings the files leave out. `import.tree` reads a node's `includePolicy` ([#1322](https://github.com/lushly-dev/afd/issues/1322)).
  - `interface.check` checks every id of a component interface, such as `violet-elements`' `tokens/interface.json`, resolves in each theme node to a value its type can hold ([#1323](https://github.com/lushly-dev/afd/issues/1323)).
  - Writes take their clock and ids from the command context's optional `now()` and `random()`, so a replayed run writes the same records; `import.json` operation ids are now random ids rather than built from the node, token and time ([#1324](https://github.com/lushly-dev/afd/issues/1324)).
  - `token.add`, `token.override`, `import.json` and `import.tree` refuse, with `INVALID_TOKEN_VALUE`, a value its type cannot hold safely in CSS; an override is held to the type of the token it overrides. A typed value must be of its kind (a real colour keyword, not any word; a number only for a number, or 0 for a length), and may use `calc()`, `clamp()`, `var()`, `oklch()`, `color-mix()` and the like. Braces inside a longer string are refused, since only a whole-value alias is followed. The CSS and SCSS exports check every token again and refuse an id that cannot be a CSS name; a composite value is still written as JSON once its keys and leaves are safe. `import.tree` checks every file, and that no node it would create exists, before it creates any. `checkCssTokenValue` and `checkCssToken` are exported from `@lushly-dev/violet-core/css` ([#1325](https://github.com/lushly-dev/afd/issues/1325)).
  - Contrast rules composite a translucent colour before measuring. A translucent background needs a `backdrop` token, the opaque surface under it; without one the rule warns instead of measuring ([#1326](https://github.com/lushly-dev/afd/issues/1326)).
  - A constraint takes `disabledReason` beside `enabled`, stored by every store (SQLite and Postgres add the column on open), and `constraints.validate` lists disabled rules with their reasons ([#1327](https://github.com/lushly-dev/afd/issues/1327)).
  - `token.remove` removes a node's own operation by id, or all of them on a token, the undo of `token.add`, refusing while another node still changes, copies, includes or references the token. New operations take one past the highest sequence, so none repeats after a removal ([#1328](https://github.com/lushly-dev/afd/issues/1328)).

## 0.3.0-preview.1

### Minor Changes

- [#1423](https://github.com/lushly-dev/afd/pull/1423) [`599be24`](https://github.com/lushly-dev/afd/commit/599be24536a5bb87c60264bd187cd698991fbc39) Thanks [@Falkicon](https://github.com/Falkicon)! - Deprecate `compare.nodes` in favour of `tokens.compare` ([#500](https://github.com/lushly-dev/afd/issues/500)), which compares two to four nodes and also counts absent and subtracted tokens; `violet compare` already runs it. `compare.nodes` will be removed in `@lushly-dev/violet-afd` 0.5.0. Until then it still works: its description starts with "Deprecated", a successful result carries a `DEPRECATED_COMMAND` warning, a `deprecated` metadata flag and a note in `reasoning`, and the HTTP API answers it with `Deprecation: true` and a `Link: </api/v1/tokens/compare>; rel="successor-version"` header, and lists it with `deprecated: true` in `GET /api/commands`. `CommandDefinition` gains an optional `deprecated` field (`{ replacement, removal }`) for other commands to use. The hosted OpenAPI document never described `compare.nodes`, so it has nothing to mark.

- [#1433](https://github.com/lushly-dev/afd/pull/1433) [`8b54f66`](https://github.com/lushly-dev/afd/commit/8b54f6664d478695eb368236c48f5d740d5ee31d) Thanks [@Falkicon](https://github.com/Falkicon)! - Component specimens for a text block (`text`), a link (`link`), a checkbox (`checkbox`) and a focus ring (`focus`), with new roles `font.family`, `line.height`, `underline`, `underline.offset`, `size`, `check`, `ring`, `ring.width` and `ring.offset`. Each role turns its value into a declaration only through an allow-list validator; `safeTextDecoration` is new in `@lushly-dev/violet-core/css`, and the checkbox's check colour is drawn through the `--violet-specimen-check` custom property. Each entry of `SPECIMEN_COMPONENTS` now lists its own `roles` and the `required` role it cannot be drawn without (the text block and link need `foreground`, the focus ring needs `ring`); `specimenComponentHasRole` checks a pair. `SPECIMEN_ROLE_NAMES` lists every role, but no component takes them all, so code that pairs roles with components should read each component's `roles`; `SPECIMEN_REQUIRED_ROLE` is deprecated in favour of `required`. `specimen.get` reports each component's own roles and its `required` role, and `specimen.set` refuses a role the component does not take, suggesting that component's roles. Button, input and card keep their ten roles.

## 0.3.0-preview.0

### Minor Changes

- [#488](https://github.com/lushly-dev/afd/pull/488) [`0a35249`](https://github.com/lushly-dev/afd/commit/0a352499b6f7417ab6a9a0a9493686b49a013776) Thanks [@Falkicon](https://github.com/Falkicon)! - `violet call <command> --schema` prints the command's input as JSON Schema instead of a serialized Zod object, and `violet --json commands` lists every command with its input schema. Core adds `toJsonSchema` and `registry.getInputJsonSchema`, which the MCP tool generator and `docs.generate` now use too, so every surface shows the same schema.

  `violet api spec` prints the hosted API's OpenAPI document (every documented `/api/v1` path), built by core's new `buildOpenApiSpec`. `--yaml` emits valid YAML, and the servers are the `--server` / `VIOLET_API_URL` deployment and the local `vercel dev` server on port 3000, which `violet api start` now uses by default. `HOSTED_EXPORT_FORMATS` moves to core.

- [#488](https://github.com/lushly-dev/afd/pull/488) [`0a35249`](https://github.com/lushly-dev/afd/commit/0a352499b6f7417ab6a9a0a9493686b49a013776) Thanks [@Falkicon](https://github.com/Falkicon)! - Deprecation plans, rule-check history and specimen role maps. Nodes carry `sunsetAt` and `replacedBy` (`node.create` / `node.update`, `violet node create|update --sunset --replaced-by`), checked on write, with warnings for a date without a replacement and a deprecated replacement; `analyze.health` reports each plan with its usage and flags `sunset-without-replacement`, `replacement-deprecated` and `past-sunset`, and `nodes.graph` carries both fields. New `analyze.snapshot` (`violet snapshot`) stores rule check results, which `analyze.trends` reads back as `recorded` per day and `summary.history`. New `specimen.get` and `specimen.set` (`violet specimen get|set`) store which tokens draw each component specimen role, on the root of each tree; the component and role lists and each role's validated declaration are in `@lushly-dev/violet-core/css`. The `Database` interface gains `addCheckSnapshot`, `listCheckSnapshots`, `getSpecimenMap` and `setSpecimenMap`; SQLite and Postgres add the columns and tables on open, safely on existing data. The demo seed plans its deprecated branch and records checks along its history. The MCP server instructions describe the new commands.

- [#488](https://github.com/lushly-dev/afd/pull/488) [`0a35249`](https://github.com/lushly-dev/afd/commit/0a352499b6f7417ab6a9a0a9493686b49a013776) Thanks [@Falkicon](https://github.com/Falkicon)! - Engine and store follow-ups:

  - `tokens.matrix` builds cells only for the rows it returns, takes `around` (with `limit`: the page holding a token) and returns `page.offset` and `page.prevCursor`. `violet matrix --around <token>`.
  - `nodes.graph` lists each node's `subtractedTokens` and traces a token without describing every other token; its reads share the resolution cache.
  - `node.get` takes `includeOperations` (`violet node get <id> --ops`).
  - Cached include, copy and reset results keep `MAX_RESOLUTION_DEPTH`, so a deep include chain fails the same way whichever node was resolved first.
  - `Database.getAuditEvents` returns events newest first and matches the same fields on memory, SQLite and Postgres.

- [#488](https://github.com/lushly-dev/afd/pull/488) [`0a35249`](https://github.com/lushly-dev/afd/commit/0a352499b6f7417ab6a9a0a9493686b49a013776) Thanks [@Falkicon](https://github.com/Falkicon)! - First release from the AFD monorepo, with Violet split into foundations, an integration and endpoints. `@lushly-dev/violet-core` is now the native token engine and no longer contains AFD commands; they moved to the new `@lushly-dev/violet-afd`, which depends on `@lushly-dev/afd-core` 2.x. The CLI and server depend on `@lushly-dev/violet-afd`. Command, registry and `CommandResult` users add `@lushly-dev/violet-afd` and import from it instead of `@lushly-dev/violet-core`, keeping the same subpath. Its re-exported `isSuccess` and `isFailure` follow afd-core 2.x and check `success` alone. `violet --version`, the server version `violet mcp start` reports, the MCP server's default version and `system.doctor`'s `packageVersion` now report the installed package version instead of `0.1.0`. See docs/features/complete/platform-monorepo/violet-transition.md.

- [#931](https://github.com/lushly-dev/afd/pull/931) [`c61365d`](https://github.com/lushly-dev/afd/commit/c61365d8908b127cd24d43a53dffaf1868eb83a7) Thanks [@Falkicon](https://github.com/Falkicon)! - Violet moves to Zod 4, commander 15 and nanoid 6. `@lushly-dev/violet-core` and `@lushly-dev/violet-afd` export Zod 4 schemas, so code that composes them needs Zod 4 too; the inferred types are unchanged. Commands accept and reject the same input as before, but a validation error's issues use Zod 4's default wording (for example "Invalid input: expected string, received undefined" instead of "Required"); custom messages, the `VALIDATION_ERROR` code and the suggestion are unchanged. Command JSON Schemas now come from Zod's `z.toJSONSchema` instead of `zod-to-json-schema` and describe the same input, with some constructs spelled differently (`oneOf` for discriminated unions, `propertyNames` on records, safe-integer bounds on integers and a pattern beside `format: "date-time"`). The `violet` CLI rejects extra command arguments ("too many arguments") instead of ignoring them; its options and help text are unchanged. nanoid 6 supports Node 22, 24 and 26 or later.
