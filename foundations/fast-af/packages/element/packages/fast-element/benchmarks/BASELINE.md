# `@lushly-dev/fast-element` Performance Baseline & Deferred `repeat` Batching Experiment (#1384)

Measured on **2026-11-23** using `node benchmarks/bench.mjs` (`pnpm -F @lushly-dev/fast-element bench`).

## Environment & Methodology

- **Browser:** Playwright headless Chromium `156.0.8078.4` (`1280x800` viewport, fresh page per run).
- **Workload:** Standard `repeat()` table benchmark (`<tr>` with class binding, id, reactive label text binding, and button, with post-run DOM text assertions verifying rendered labels and `update-10th` `" !!!"` mutations) plus `scoped-create-1k` (1,000 rows instantiating a `<scoped-chip>` `FASTElement` inside a native scoped `CustomElementRegistry` shadow root).
- **Metrics:**
  - **JS time:** `performance.now()` around state mutation + synchronous `Updates.process()` flush (removes 16.67ms `requestAnimationFrame` quantization).
  - **Paint time:** `performance.now()` through double `requestAnimationFrame` (captures JS + Blink style, layout, and paint).
- **Statistics:** 3 warmup runs + 15 measured runs per scenario; A/B runs use 15 balanced interleaved pairs (`A,B` / `B,A`) to cancel thermal and GC drift, with tie-aware exact two-sided paired Wilcoxon signed-rank `p`-values.

## 3. Deferred `repeat` Batching Experiment (`current` vs `batched`)

**Hypothesis:** Batching newly created `HTMLView` instances in `RepeatBehavior.refreshAllViews()` (`viewsLength === 0 && itemsLength > 1`) and `RepeatBehavior.updateSplicedViews()` (`!recycle || availableViews === 0`) into a shared `DocumentFragment` via `HTMLView.prototype.appendTo(batch)` and performing a single `parent.insertBefore(batch, location)` (falling back to `view.insertBefore(location)` for custom `SyntheticView`s) might reduce DOM insertion overhead on large creates and appends. The candidate ESM directory is reproducibly generated by `benchmarks/build-batched-candidate.mjs`.

| Scenario | current JS | batched JS | JS delta | JS p | current Paint | batched Paint | Paint delta | Paint p |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `create-1k` | 9.30ms | 12.00ms | +29.0% | 0.0009 | 65.90ms | 66.50ms | +0.9% | 0.0266 |
| `create-10k` | 109.50ms | 129.20ms | +18.0% | 0.0001 | 629.90ms | 629.10ms | -0.1% | 0.1205 |
| `append-1k` | 10.70ms | 12.50ms | +16.8% | 0.2166 | 66.20ms | 66.90ms | +1.1% | 0.6895 |
| `replace-1k` | 4.60ms | 4.80ms | +4.3% | 0.8585 | 32.50ms | 33.00ms | +1.5% | 0.3969 |
| `update-10th` | 0.60ms | 0.60ms | +0.0% | 0.8994 | 33.00ms | 33.20ms | +0.6% | 0.2235 |
| `swap-rows` | 0.50ms | 0.50ms | +0.0% | 0.8750 | 32.90ms | 33.30ms | +1.2% | 0.1475 |
| `select-row` | 1.40ms | 1.40ms | -0.0% | 0.4744 | 33.10ms | 33.10ms | +0.0% | 0.5332 |
| `clear-1k` | 5.30ms | 5.40ms | +1.9% | 0.1302 | 33.80ms | 33.40ms | -1.2% | 0.6285 |
| `scoped-create-1k` | 18.00ms | 19.50ms | +8.3% | 0.0012 | 49.20ms | 49.60ms | +0.8% | 0.2465 |

### Decision: **Reject — keep `repeat.ts` unbatched**

`DocumentFragment` batching is **statistically significantly slower** on the exact scenarios it targeted:
- `create-1k`: **+29.0% JS** (`p = 0.0009`), **+0.9% Paint** (`p = 0.0266`).
- `create-10k`: **+18.0% JS** (`p = 0.0001`), flat Paint (`-0.1%`, `p = 0.1205`).
- `scoped-create-1k`: **+8.3% JS** (`p = 0.0012`), flat Paint (`+0.8%`, `p = 0.2465`).
- `append-1k`: **+16.8% JS** median (`p = 0.2166`), flat Paint (`+1.1%`, `p = 0.6895`).

**Why:** Every `HTMLView` already wraps its cloned template nodes in its own `DocumentFragment` (`this.fragment`), and Blink already defers style and layout until after the JavaScript turn. Moving nodes from each view's fragment into an intermediate `batch` `DocumentFragment` and then moving all `N` rows a second time into `location.parentNode` performs 2x DOM reparenting with zero layout benefit.

`src/templating/repeat.ts` is therefore left unchanged.

```bash

pnpm -F @lushly-dev/fast-element bench

# Reproduce the deferred repeat batching A/B:

  --ab foundations/fast-af/packages/element/packages/fast-element/dist/esm /tmp/batched-repeat \
  --label-a=current --label-b=batched --runs=15 --warmup=3

  --ab /tmp/ms-314/package/dist/esm foundations/fast-af/packages/element/packages/fast-element/dist/esm \
  --label-a=microsoft-3.1.4 --label-b=fast-af --runs=15 --warmup=3
```
